# Dynamic Load Balancing under Restricting Updates 

Aaron Bernstein ∗ Sayan Bhattacharya † Peter Kiss ‡ Thatchaphol Saranurak §

Abstract 

We study the problem of load balancing in the dynamic setting. The input is a bipartite graph 

G = ( J ∪ M, E ) of jobs J and machines M . Every job has a positive weight w(j). The goal is to assign every job in J to an adjacent machine in M so as to minimize the maximum machine load, where the load of a machine is the sum of the weights of the jobs assigned to it. Although load balancing has been studied extensively in many models of computation, the only previous result in the dynamic model addresses the incremental setting, where updates take the form of edge insertions and job deletions [BKS23b]. The authors show a (1 + ϵ)-approximation for incremental fractional load balancing with poly(log( n), 1/ϵ ) update time; they point out that their techniques do not extend to the decremental setting. 

Main Result: We obtain a near-optimal algorithm for fractional load balancing in the decre-mental setting, where updates take the form of edge deletions and job insertions: a (1 + ϵ)-approximation with poly(log( n), 1/ϵ ) update time. Our techniques are very different from those of the incremental algorithm of [BKS23b]. Instead, our algorithm is inspired by a load-balancing algo-rithm from the congest model of computation [ALPZ21]. We develop a novel analytic framework for this algorithm, which allows us to show that it performs well in the dynamic setting. 

Rounding Scheme: We also present a black-box rounding scheme for dynamic load balancing. Plugging in our fractional algorithm, we obtain a decremental algorithm for (2 + ϵ)-approximate 

integral load balancing with poly(log( n), 1/ϵ ) update time. We also obtain the same bounds for incremental load balancing by plugging in the fractional algorithm of [BKS23b]. The approximation ratio nearly matches the 2-approximation achieved by the state-of-the-art static algorithms for this problem.

We study the load balancing problem in the dynamic setting. The input is a bipartite graph G =(J ∪ M, E ), where we refer to the vertices in J as jobs, and those in M as machines. Each job also has a positive weight w(j). The goal is to find an assignment from jobs to adjacent machines that minimizes the maximum machine load, where the load of a machine i is defined as the sum of the weights of all jobs assigned to i.There is a rich literature on load balancing in many models of computation, from standard ap-proximation algorithms [LST90, ST93, Sve11, JR20], to classic online algorithms [ANR95, AAF +97], streaming algorithms [KR16, ABL23, ABL +25], and parallel/distributed algorithms [You01, MRWZ16, Li23, HKPSR18, ABL20, ALPZ21]. One particularly relevant line of research is online algorithms with recourse, where the graph is changing over time, and the goal is to upper-bound how often the (ap-proximately) optimal assignment needs to change [GKS14, BEM22, KLS23, FGK24]. But the results for this model do not provide efficient algorithms for actually maintaining the assignment – that is the goal of dynamic algorithms. 

Dynamic Load Balancing: In the fully dynamic model, each update either inserts or deletes an edge in the graph, and the goal is to maintain an approximately optimal assignment with small update time. There are also two commonly studied special cases, which are called partially dynamic 

models: in the incremental (resp. decremental) model the only allowed updates are edge insertions (resp. deletions) and job deletions (resp. insertions); in short, updates in the incremental model can only decrease the optimum max load, while those in the decremental model can only increase it. Despite the rich literature on load balancing in other models, the only result we know of on dynamic load balancing is an algorithm of [BKS23b] for incremental load balancing: they maintain a (1 + ϵ)-approximate fractional assignment in total update time ˜O(m), which implies amortized update time poly(log( n)/ϵ ). However, the authors of [BKS23b] note that their techniques fail to extend to the decremental setting. Our main result obtains the same bounds in the decremental setting. We also develop a black-box rounding scheme to produce an integral assignment. We thus essentially settle the complexity of the problem for partially dynamic algorithms. One of the reasons to focus on the partially dynamic model is that similarly strong results for the fully dynamic model are currently beyond our reach, even for the much simpler problem of dynamic matching; see the discussion in Section 1.2 on the relationship to matching. 

1.1 Our Contributions 

Our main contribution is a nearly optimal algorithm for fractional load balancing in the decremental model. 

Theorem 1.1. Let G = ( J ∪ M, E ) be a graph with job weights in [1 , W ] that is subject to a sequence of edge deletions and job insertions. There is an algorithm that maintains a fractional assignment whose maximum machine load is a (1 + ϵ)-approximation to the optimum. The total update time is 

O(m poly(log( nW )/ϵ )) , where m is the total number of edges ever present in the graph and n = |J ∪M |

is the total number of nodes at the end of the last update. 

We also design a black-box rounding scheme, which is based on an earlier rounding scheme of [KLS23] for online algorithms, but makes several significant modifications to ensure efficient update time. Applying the rounding scheme (Section 7) to Theorem 1.1 yields the following integral algorithm: 

Theorem 1.2. Let G = ( J ∪ M, E ) be a graph with job weights in [1 , W ] that is subject to a sequence of edge deletions and job insertions. There is a randomized algorithm that maintains an integral 

assignment whose maximum machine load is a (2 + ϵ)-approximation to the optimum, using total 

1update time O(m poly(log( nW )/ϵ )) with high probability. In fact, the approximation guarantee is slightly stronger: each machine in our assignment has load at most (1 + ϵ) · Opt + W ≤ (2 + ϵ) · Opt .The algorithm works against an adaptive adversary. 

The approximation ratio of the integral algorithm is essentially the best we can hope for: it matches up to a (1 + ϵ) factor the best-known polynomial-time algorithms in the static setting [LST90, ST93]. 1

Applying our black-box rounding scheme to the incremental (fractional) algorithm of [BKS23b] also yields the first efficient algorithm for incremental integral load balancing; the bounds are the same as in Theorem 1.2. 

1.2 Related Work: Maximum Flow and Maximum Matching 

Our results have significant connections to dynamic algorithms for several related problems. 

Maximum Flow: It is not hard to check that incremental/decremental load balancing is a spe-cial case of incremental/decremental maximum flow. There is an algorithm for incremental (1 + ϵ)-approximate maximum flow with update time no(1) [CKL +24]. This same algorithm thus also solves incremental load balancing, although the algorithm is significantly more complicated than the incre-mental load balancing algorithm of [BKS23b] and has update time no(1) rather than polylog. In the decremental setting, by contrast, while there exists a recent flow algorithm with the same no(1) update time [vdBCK +24], that algorithm cannot actually maintain the approximate assignment itself ; it only maintains a single number, which is an approximation to the optimum max load. Ours is thus the first efficient algorithm to maintain the assignment itself in the decremental setting. 

Matching: Load balancing can be viewed as a generalization of the matching problem. There is a long line of work on this problem in partially dynamic settings, and here too efficient incremental algorithms [Gup14, GLS +19, BK23] came before decremental ones [BGS20, JJST22, ABD22, Dud24, CST25]. The connection to matching also implies a crucial barrier for our problem. Even for the simpler problem of matching, a fully dynamic (1 + ϵ)-approximation in polylog (or even n1−Ω(1) ) update time is not known, and this is widely considered one of the main open problems in the field. In fact, there are conditional lower bounds that rule out such a result if we seek a polynomial dependence on 1 /ϵ [Liu24]. At the same time, it is not hard to show that a (1 + ϵ)-approximation for fractional 

load balancing would immediately imply the same bounds for fully dynamic integral matching; see Appendix A for details. Generalizing our (1 + ϵ)-approximate decremental load balancing algorithm to the fully dynamic setting is thus out of reach, as we should first aim to understand the simpler problem of fully dynamic (1 + ϵ)-approximate matching. That still leaves open the question of whether one can get an efficient algorithm for fully dynamic load balancing with a worse approximation. We show a conditional lower bound which proves that even in unweighted graphs, a 2 − Ω(1)-approximation for integral load balancing requires large update time (Appendix B). But neither upper nor lower bounds are known for approximation better than 2. Matching is no longer a barrier here, as an efficient algorithm for fully dynamic 2-approximate matching is known [BGS11, Sol16]. At the same time, load balancing is a significantly harder problem than matching, and in fact there are models of computation where it is provably much harder [ABL +25]. We leave it as an open question whether there exists an efficient algorithm for O(1)- or even polylog-approximate fully dynamic load balancing, or whether there are conditional lower bounds suggesting such bounds are not possible.

# 2 Overview 

We give an informal overview of the two main ingredients of the paper. First, we explain a dynamic algorithm for maintaining a nearly optimal fractional assignment in Section 2.1. Second, we explain in Section 2.2 a black-box dynamic rounding algorithm that converts such a fractional assignment into an integral assignment with only a small additional loss.

Starting point: CONGEST Algorithm. The starting point is an extremely simple multiplicative-update algorithm from the congest literature by Ahmadian, Liu, Peng, and Zadimoghaddam [ALPZ21]. Each job j and each machine i has a nonnegative integer level, denoted by ℓ(j) and ℓ(i), initialized ats zero. The algorithm maintains a flow value on each current edge ( j, i ) of the form 

x(j, i ) = η · (1 + ϵ)ℓ(j)−ℓ(i),

where η > 0 is a very small number; for the unweighted overview, one may take η = n−20 . Increasing the level of a job multiplies all of its incident flow values by (1 + ϵ), while increasing the level of a machine divides all of its incident flow values by (1 + ϵ). We call these two operations boosting the job and whacking the machine. The algorithm repeatedly performs the following local repairs. If some machine has load larger than (1 + ϵ)β, we whack it. Otherwise, if some job sends less than 1 /(1 + ϵ) total flow, we boost it. We always give priority to whacking machines before boosting jobs. This priority rule ensures that every machine has load at most (1 + ϵ)2β < 2β throughout the algorithm. When the local repair loop stops, every job sends at least 1 /(1 + ϵ) flow and every machine receives load at most (1 + ϵ)β, as desired. Thus, the only remaining issue is to prove that the repair loop cannot run for too long while x∗ exists. Equivalently, we need to prove the following key claim. 

Key claim. If the current instance admits an assignment of maximum load one, then no job or machine can reach level Lmax = poly(log n, 1/ϵ ). 3Once this claim is known, the total running time is immediate. A boost or whack costs time propor-tional to the current degree of the vertex being updated. Since each edge is charged only when one of its endpoints increases level, and each endpoint increases level only Lmax times, the total update time is ˜O(mL max ), near-linear in the number of edges that ever appear.

Why deletions break the warm-up. Under edge deletions, the sentence “every machine i with positive level receives flow at least x(i) ≥ β” is completely false. While the load of machine i is still at least β right after being whacked, it may decrease arbitrarily later because incident edges are deleted.

Similarly, for every machine i and every level k that i has ever reached, it contains a machine-level node (i, k ) ∈ M . 2.2 Rounding the Dynamic Fractional Assignment 

The fractional algorithm maintains a (1 + O(ϵ))-approximate fractional assignment. We now explain how to round a dynamic fractional assignment with maximum load Γ and maximum job weight W to an integral assignment with maximum load (1 + ϵ)Γ + W .7Background: the Shmoys Tardos slot graph. The starting point is the classical Shmoys Tardos rounding scheme. Let G = ( J ∪ M, E ) be an input graph with maximum job weight W and x be a fractional assignment with load Γ. Shmoys and Tardos construct a slot graph H = ( J ∪ S, E H ) whose left side is the set of jobs and whose right side is obtained by replacing each machine i with a set of 

slots S(i) ⊆ S.The key property is that any job-perfect matching in H gives an integral assignment in the original instance: if job j is matched to a slot of machine i, then we assign j to i. Moreover, the load of the resulting integral assignment is Γ+ W . Thus, using the fractional assignment, they reduce the problem of finding a (weighted) assignment to that of finding an (unweighted) perfect matching. 

The online rounding framework of KLS. Krishnaswamy, Li, and Suriyanarayana [KLS23] showed how to adapt the Shmoys–Tardos rounding scheme to the online setting. Given a graph G

and a fractional assignment x undergoing updates, the goal here is to maintain an integral assignment with low recourse , i.e., a small number of reassignments. They define a similar slot graph H = ( J ∪ S, E H ) with a slightly weaker approximation: any job-perfect matching in H yields an integral assignment of load (1 + O(ϵ))Γ + W . However, their slot graph H has nicer structural properties: 1. (Vertex expansion): every set A of jobs has at least (1 + Ω( ϵ)) |A| neighboring slots, and 2. (Stable slots) : the number of slot insertions and deletions is bounded in terms of the number of updates to x.2

The algorithm of [KLS23] simply maintains the slot graph H and a job-perfect matching MH in H.Whenever MH is not perfect, they simply augment through an O( log nϵ )-length augmenting path; such a short path is guaranteed to exist by the vertex expansion of H and induces only O( log nϵ ) recourse. Vertices in MH are not unmatched often because slots are stable. These facts imply a left-perfect matching with small recourse, but not yet with small update time .

Barriers to making KLS fast. There are two barriers. 1. (Representation barrier) : Edges of H are not stable. A small change in the fractional assignment x can change many edges of the slot graph H. Thus explicitly maintaining all edges of H will be too expensive. 2. (Algorithmic barrier): Even if we ignore the representation issue, we do not know a fast fully dynamic algorithm for maintaining a left-perfect matching in a changing bipartite graph merely from the promise that the graph has vertex expansion 1+ ϵ. Expansion guarantees that a perfect matching exists, but it does not directly tell us how to find short augmenting paths quickly after dynamic updates. 

Our strategy: random augmenting path based on fractional matching with gap. Based on the fractional assignment x in G, [KLS23] also defined a fractional assignment y with a gap guarantee: each job j sends y(j) = 1 unit and each slot s receives at most y(s) < 1 − 2ϵ units. They used y

in the analysis to prove the vertex expansion of H and the approximation guarantee of a left-perfect matching in H.Our key observation is that y is, in fact, extremely helpful algorithmically , not just in analysis. Moreover, although y changes substantially under updates, as H does, we can still implicitly maintain it. Suppose for the moment that we have oracle access to y. We can explicitly maintain a left-perfect matching MH in the slot graph H undergoing fully dynamic updates with only ˜O(1 /ϵ ) update time.     

> 2In fact, it is O(1 /ϵ 2) times the total ℓ1change of x.

8Whenever a job becomes unmatched, we can very quickly repair the matching by finding a random augmenting path from this unmatched job: Starting from the current unmatched job j, we sample a neighboring slot s with probability proportional to y(j, s ). If s is unmatched, we have found an augmenting path and we augment along it. If s is matched, we follow the matching edge from s to the job currently matched to s, and then repeat the same sampling step from that job. The reason this walk is short is exactly the gap in y: each job sends at least 1 unit, but each slot receives at most 1 − 2ϵ units. Intuitively, when the walk samples according to y, the matched slots cannot absorb all of the probability forever, because the slot side has slack. At each step, a constant Ω( ϵ) fraction of the remaining probability reaches unmatched slots. Therefore the augmenting-path length is O(log( n)/ϵ ) with high probability. This bounds the update time of ˜O(1 /ϵ ) as well. Thus, the fractional assignment y with a gap guarantee is stronger than merely the graph H with vertex expansion. This allows us to maintain a left-perfect matching and overcome the algorithmic barrier above. 

Dynamic rounding without explicit slot graph. The simplicity of the random augmenting path algorithm allows us to work without explicitly storing the full slot graph H or the fractional assignment y, overcoming the representation barrier too. Indeed, the random walk needs only very limited access to y: given a job j, sample a slot s with probability proportional to y(j, s ); given a slot 

s, determine whether it is matched and, if so, to which job; and after an update, identify the small set of slots or matched jobs whose status may have become invalid. These operations can be supported implicitly. For each machine i, its slots S(i) form an ordered set of intervals. Using standard interval data structures, given a job-machine pair ( j, i ), we can find O(1) slots s of machine i where ( j, s ) ∈ EH , as well as sample a neighbor of j according to the y-distribution. Thus the algorithm never materializes all edges of H. The explicit object we maintain is only the integral matching MH , plus compact interval data structures that allow the required sampling queries. Updates to the fractional assignment may implicitly change many edges of H, but will lead to few slot updates because slots are stable. Each slot update can unmatch one job. Each unmatched job can be repaired very quickly by a short random augmenting path. Hence, the final update time is small. 

Putting the pieces together. The fractional algorithm supplies a dynamic fractional assignment with load 1+ O(ϵ) and bounded total change. The rounding algorithm treats this fractional assignment as a black box, maintains the implicit slot graph H and the matching MH , and repairs the matching 

MH using short random augmenting paths guided by y. Combining the two parts gives a decremental algorithm for load balancing under edge deletions with near-linear total update time and integral load (1 + O(ϵ))Γ + W .We note that the rounding framework is completely black-box and could be applied to other dynamic fractional load-balancing algorithms as well, whether decremental, incremental, or fully dy-namic. For example, we can apply it to the incremental algorithm of Bhattacharya, Kiss, and Sara-nurak [BKS23b].

In this section, we present our algorithm for rounding a dynamic ϵ-fractional assignment. We restate the theorem summarizing the guarantees of our rounding framework for convenience. 

Theorem 4.2. Let (Gt = ( Jt ∪ Mt, E t), w t) be a dynamic load balancing instance with maximum job weight W . Let xt denote an ϵ-fractional assignment at time t with maximum load Γt. Over a sequence of updates to the instance (which could consist of both edge and vertex insertions and deletions), let U

denote the total number of edge updates to the fractional assignment xt.There exists a randomized dynamic algorithm that, given access to Gt, w t, x t, maintains an integral assignment of (Gt, w t) with maximum load at most (1 + O(ϵ))Γ t + W at time t. The algorithm has total update time ˜O(( m + U )/ϵ 3) with high probability and works against an adaptive adversary.

# B 2 − ϵ-Approximation Hardness for Full Dynamic Load Balancing 

In this section, we show that the existence of a better-than-2-approximate algorithm with o(n) update time for the unweighted fully dynamic load balancing problem would violate the OMv conjecture [HKNS15]. 

The hardness assumption. We use the following standard consequence of the OMv conjecture. In the OuMv problem, after preprocessing a Boolean matrix A ∈ { 0, 1}n×n, an algorithm receives n

online pairs of Boolean vectors ( ut, v t) ∈ { 0, 1}n × { 0, 1}n, and after receiving ( ut, v t) must output (ut)⊤Av t = _

> i,j ∈[n]

(uti ∧ Aij ∧ vtj )before seeing the next pair. Under the OMv conjecture, for every constant γ > 0, OuMv cannot be solved with polynomial preprocessing and total online time O(n3−γ ). 

Theorem B.1. Assume the OMv conjecture. For every pair of constants ε, δ > 0, there is no fully dynamic (2 − ε)-approximation algorithm for bipartite load balancing with polynomial preprocessing, amortized update time O(N 1−δ), and query time O(N 2−δ), where N = |J| + |M |. In particular, if the maintained assignment value is explicitly available after every update, then there is no such algorithm with amortized update time O(N 1−δ).Proof. Suppose, toward contradiction, that such a dynamic algorithm D exists. We show how to solve OuMv in truly subcubic time. Let A ∈ { 0, 1}n×n be the OuMv matrix. From A, construct a bipartite graph G = ( J ∪ M, E ). The job side is 

J = {x, y } ∪ { ai : i ∈ [n]} ∪ { bj : j ∈ [n]},

and the machine side is 

M = {p} ∪ { ri : i ∈ [n]} ∪ { cj : j ∈ [n]} ∪ { fj : j ∈ [n]}.

Thus N = |J| + |M | = 5 n + 3 = Θ( n). The static edges are (y, p ), (x, p ), (ai, r i) ∀i ∈ [n], (bj , c j ) ∀j ∈ [n], (ai, c j ) iff Aij = 1 .

Now run D on this dynamic graph. After the updates for the current pair ( u, v ), query the value of the maintained assignment. If u⊤Av = 1, then OPT( G) = 1, so a (2 − ε)-approximation must have load at most 2 − ε < 2. Since loads are integral, the maintained load is exactly 1. If u⊤Av = 0, then OPT( G) = 2, so every feasible assignment has load at least 2. Therefore the maintained load is 1 if and only if u⊤Av = 1. This solves the current OuMv query. It remains to bound the running time. The graph has N = Θ( n) vertices. Over all n online pairs, there are at most 2 n2 edge updates and n queries. Therefore the total online time of the resulting OuMv algorithm is 

O(n2 · N 1−δ + n · N 2−δ) = O(n2 · n1−δ + n · n2−δ) = O(n3−δ).

The preprocessing of D is polynomial in the initial graph size and hence polynomial in n, so it is allowed by the polynomial-preprocessing version of OuMv hardness. We have obtained an O(n3−δ)-time online algorithm for OuMv after polynomial preprocessing, contradicting the OMv conjecture. This proves the theorem.
