## 摘要
异构机器人团队能够通过结合跨多种具身形态的互补感知、移动与操作能力，实现复杂的长时程任务。然而，现有系统难以将执行时的修正保留为可复用经验，难以在空间和时间上维护与任务相关的上下文记忆以实现可靠交接，也难以显式表示结构化协作所需的机器人间依赖关系。为解决这些挑战，我们提出 InstAgent，一种面向异构机器人协作的递归自我改进（RSI）智能体操作系统。InstAgent 将团队行为组织为智能体行为树（BTs），显式建模能力分配、机器人间依赖关系与交接检查。RSI 机制根据执行反馈更新这些协作程序，并保留成功的修订以供未来任务复用；同时，共享的多模态时空记忆为规划与交接验证提供上下文。在 20 个真实世界多机器人任务上使用三种高层模型的实验表明，其在任务成功率、首次尝试完成率和执行效率方面均取得一致提升。

## Abstract
Heterogeneous robot teams enable complex, long-horizon tasks by combining complementary sensing, mobility, and manipulation capabilities across multiple embodiments. Yet existing systems struggle to retain execution-time corrections as reusable experience, maintain task-relevant context memory across space and time for reliable handoffs, and explicitly represent the inter-robot dependencies required for structured collaboration. In order to address these challenges, we present InstAgent, a recursively self-improving (RSI) Agent Operating System for heterogeneous robot collaboration. InstAgent organizes team behaviors as agentic behavior trees (BTs) that explicitly model capability assignment, inter-robot dependencies and handoff checks. The RSI mechanism updates these collaboration programs from execution feedback and preserves successful revisions for reuse in future tasks, while shared multimodal spatio-temporal memory provides context for planning and handoff validation. Experiments on 20 real-world multi-robot tasks with three high-level models show consistent gains in task success, first-attempt completion, and execution efficiency.

## 1. 核心问题与研究动机

- **背景**：异构机器人团队（人形、四足、机械臂等）通过互补的感知、移动与操作能力，可完成单一具身难以胜任的长时程任务。但这类任务不是简单的“把技能分给不同机器人”，因为机器人分布在不同地点与阶段，前一个机器人的结果往往决定后一个能否开工，涉及**显式的跨机器人依赖与交接条件**。
- **LLM 智能体系统的潜力**：把高层推理、异构技能调用、多模态感知与执行反馈接入闭环，适合长时程、流程无法事先完全指定的协作场景。
- **论文指出三个尚未解决的挑战**：
  - **经验不可沉淀**：复杂物理任务极少一次规划成功，但执行中的修正往往是“任务局部”的，未被累积为后续任务可继承、可继续改进的**可执行经验**（现有反思/技能复用工作未保留协作流程的修正）。
  - **跨时空上下文缺失**：长时程协作需要超越当前局部观测的持久时空记忆，而现有记忆系统虽支持空间/时间检索，却未把历史观测与**当前物理交接检查**打通。
  - **协作结构被扁平化**：把异构机器人视为一堆可调用技能，会遗漏机器人间依赖、交接条件与恢复逻辑，仅靠孤立技能调用不足以支撑可靠执行。
- **整体含义**：论文主张把“团队协作流程”本身当作可执行、可验证、可修订、可继承的**程序资产**（行为树），并让执行反馈递归地改进这一资产，从而把一次性纠错转化为团队的累积能力。

## 2. 方法论

### 2.1 核心思想
- 构建基于 **ROS 2** 的智能体操作系统，将异构机器人协作表示为**协作行为树（Collaboration BT）**，显式编码能力分配、机器人间依赖、交接检查与恢复分支。
- 形成闭环：**组合（Compose）→ 执行（Execute）→ 验证（Verify）→ 修订（Revise）→ 保留复用（Retain/Reuse）**。
- 关键概念区分：论文把 RSI 分为两类，并**同时采用**：
  - **Experience-Context RSI**（如 Reflexion）：把反馈存为文档化经验，靠智能体当前推理落地；
  - **Structured-Program RSI**（如 Voyager、LRLL）：把经验固化为可执行程序结构，保留条件、执行顺序与恢复分支。
  - InstAgent 用前者指导修订、用后者保存修订结果，二者以“**文档–BT 配对**”形式绑定。

### 2.2 四个技术组件

**（a）Skill BT：原子技能 → 可执行最小树**
- 技能来自共享模块（导航、感知）与机器人模块（运动、语音交互、操作）。
- 每个具体技能调用被**确定性包装**为只含一个 Action 节点的最小行为树：`skill` 字段标识 `module/skill` 接口，`args` 携带调用参数。
- MLLM 读取功能描述、接口定义、调用上下文与使用条件，转成 RSI 库通用的技能表示；每条经验记录用途、参数含义、使用约束，并与注册接口保持一致。
- 执行前检查 BT 格式、接口是否存在、参数与 schema 一致性；运行时解析的参数在解析后再校验。

**（b）HeteroComposer：协作 BT 构建**
- 检索–筛选–取结构的三步流程（式 1）：
  - `D_cand = RetrieveDocs(D_k; g_k, x_k,0)`：按任务目标与上下文检索候选文档；
  - `D_sel = Select_MLLM(D_cand; g_k, x_k,0)`：由 MLLM 依据文档中的目标与适用范围筛选；
  - `E_k = {(d, T_k[ℓ(d)])}`：通过 `ℓ(d)` 取出文档关联的子树，形成“文档+程序”经验集。
- 智能体优先复用已有程序结构，未覆盖的步骤用原子技能补齐；依据可用能力集 `S_k` 为各动作选择机器人/模块并绑定任务相关参数。
- 跨机器人协调通过 BT 中的**序列、条件、恢复分支**表达，后序动作在前置条件满足后即可启动。

**（c）Collab-RSI：经验引导的协作 BT 演化**
- 触发条件：交接失败、执行依赖未满足、恢复过程不足。
- 修订粒度两类：
  - **子树内部结构**（如新增结果检查节点）；
  - **子树之间关系**（调整动作分配、交接条件、跨机器人恢复路径）。
- 修订后先做结构与技能接口检查，再**重新执行**以验证交接条件与任务结果；只有通过验证的修订才写回经验库。
- 写回内容：BT 结构保留依赖、交接检查与恢复流程；配对文档记录任务目标、所需能力与机器人角色、适用条件、失败上下文、修订理由；失败的执行记录也保留为诊断上下文。
- 持久化更新形式化为 `(D_{k+1}, T_{k+1}) = Update(D_k, T_k, τ_k, v_k)`。
- 组合出的多子树复合程序可作为**新的可复用单元**整体入库，使“组合本身”也可被检索复用。
- **算法 1 流程**：观测 → 选经验 → 组合并检查 → 循环 {执行并验证；若成功/预算耗尽/终止则退出；确认安全停止；最多 `J_max=3` 个候选修订并检查；重建补全检查、预算减一} → 若写标志 `w=1` 则更新库 → 返回结果、轨迹与更新后的库。

**（d）SMAR-T：共享多模态时空记忆 + 智能体驱动检索**
- 每条记忆条目 `m_i = (I_i, c_i, z^v_i, z^c_i, p_i, t_i, r_i)`：图像、VLM 生成的字幕、视觉嵌入、字幕嵌入、共享地图中的位姿（位置 `x_i∈R³` + 朝向 `R_i∈SO(3)`）、时间戳、来源机器人。
- 位姿/时间/来源三元信息把跨机器人、跨任务阶段的观测关联起来，可用于诊断“载荷丢失”类失败并据此修订交接检查。
- 三种只读检索工具，均在搜索域 `U ⊆ H` 内进行并保留全部元数据：
  - **位置工具**：按 `d_p(i|x̂)=‖x_i−x̂‖₂` 排序（仅用位置分量，朝向留给导航）；
  - **时间工具**：按 `d_t(i|t̂)=|Δt_i−t̂|` 排序（观测与查询时间以同一场景原点计）；
  - **语义工具**：先按视觉相似度召回至多 10 帧，再用字幕对这 10 帧重排，`s_i=(1−λ)ṽ_i+λũ_i`，`λ=0.15`，返回至多 5 个候选（`ṽ`、`ũ` 为 C10 内 min–max 归一化）。
- **智能体检索循环**：分解语义/空间/时间约束 → 选择工具与搜索域 → 每次调用后**联合评估图像、字幕与元数据**是否满足原始约束 → 不足则继续检索（可回到全量记忆），每次真实机器人查询最多 10 次调用 → 证据不足则报告并可能请求新观测；证据充分则给出有依据的回答，并按需驱动 BT 构建或修订。
