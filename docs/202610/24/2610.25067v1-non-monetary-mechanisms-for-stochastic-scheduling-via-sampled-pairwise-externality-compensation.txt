Abstract 

How can a shared resource be allocated without money when agents have private, stochastic de-mands that can be queued for a while, and may behave strategically, or even adversarially? We in-troduce a paradigm for non-monetary online resource allocation called Sampled Pairwise Externality Compensator (SPEC ). Our objective is to guarantee each agent a large fraction of its ideal utility : an individual benchmark corresponding to serving the highest-valued fraction of its demand permitted by an equal share of capacity. We seek guarantees that hold regardless of other agents’ behavior, in-cluding potentially adversarial and collusive behavior. Our approach builds on the idea of pairwise externality compensation, making it computationally efficient by replacing exact calculations of fu-ture externalities with sampled estimates. The central insight is that local mixing, exploited through coupled simulations, allows these estimates to be computed efficiently while preserving robust utility guarantees. In our main technical contribution, we instantiate SPEC in a stochastic scheduling model in which agents receive jobs with private values, unserved jobs persist across periods subject to ran-dom expiration, and a single server processes at most one job per period. Our mechanism gives each agent a simple strategy that achieves the optimal worst-case fraction of ideal utility available to a fully informed planner, up to a sublinear additive loss in total utility. We also show that this fraction ap-proaches 1 in the long-horizon limit as the expiration probability vanishes: sufficiently persistent jobs allow each agent to secure nearly its full ideal utility. The mechanism runs in 𝑂 (𝑛 2) expected amortized time per period, where 𝑛 is the number of agents; significantly, the expected amortized computational overhead per period is independent of the time horizon 𝑇 .

Consider the problem of repeatedly allocating a resource among multiple agents: a growing line of work shows how to do so in fair and efficient ways without the use of money [BFT23; FBT25; GBI21b; GCR09; Lin+26a; Lin+25; Lin+26b; Ony+25]. A canonical model in this literature assumes that a request loses its value if it is not served immediately; this is partly for modeling simplicity, but also meaningful in applications like allocating time on a telescope, where a team aiming to observe an event in the sky needs the equipment when the event happens. A more general model of intertemporal dependence is one where unserved jobs can remain available for future service for a while, but then expire. An increasingly relevant example is ML training: for example, Google’s internal Quota Marketplace uses dynamic pricing to allocate shared training resources [Siv+26]. These workloads can have different values and delay tolerances (i.e., some may still be useful to do tomorrow). This motivates the core model we study in this work. 1

Consider an organization (university/company) controlling access to a computing cluster shared between multiple competing agents (labs/teams). This setting exhibits several features. • The computing cluster is a limited resource. In general, the demand for it exceeds its capacity. • Labs have uncertain and varying demand for the cluster over time. Sometimes, labs have a lot of impor-tant jobs that they wish to run and other times, they have few. • If a lab has an important job to run but the cluster is busy with other labs’ jobs, they’ll still likely want to run the job later when the cluster becomes available. However, if a lab does not get to run its job for too long a time, the lab becomes no longer interested in processing that job. For example, perhaps the conference deadline for the job passed. • The allocation procedure should be efficient and fair without charging the labs money. Furthermore, it is unclear from the department’s perspective how to evaluate which labs should be given access to the cluster at each time. For example, asking each lab to rate each of their jobs’ importance on a scale 1– 10 and giving access to the jobs that have the highest ratings has several flaws: different labs may have different interpretations for how important a particular rating like 7 may be, or labs may act strategically and always report 10. • The allocation procedure should be simple; it should be easy for agents to understand, and participate in a way to be able to obtain access to the cluster when they need it most. We consider a simple model for settings like these as follows. There is a fixed set of 𝑛 agents for a long time horizon 𝑇 . Each agent maintains a queue of jobs. In each time period 𝑡 ∈ { 1, 2, . . . ,𝑇 }, each agent 

𝑖 receives a job in their queue with value drawn from some distribution F𝑖 i.i.d. across time. There is a single server that can process at most one job in each time period. Unserved jobs expire with probability 

𝛿 ; unexpired jobs remain in their corresponding queues to the next time period. A principal decides which agent gets access to the server at each time period via some mechanism without knowledge of the agents’ queue states, including the job values and how many jobs are in each agent’s queue at any time. Each agent seeks to maximize the sum of the values of served jobs. Previous work has introduced the benchmark of ideal utility to quantify the efficiency and fairness of a mechanism; we continue to use this in our more general setting. Roughly speaking, the ideal utility of agent 𝑖 is the utility they would receive if their highest-valued 𝑇 /𝑛 jobs were processed. This is a reasonable upper bound for what an agent should receive in a “fair” world: at most 𝑇 total jobs can get processed, so an agent should only hope to process their highest-valued 𝑇 /𝑛 jobs. Notably, this benchmark is easy to compute: it depends only on the agent’s own value distribution and the number of players, and does not require an analysis of other agents’ demands or strategies. Note that the ideal utility does not depend on 𝛿 : it simulates an ideal world where the agent does not have to queue jobs at all, immediately serving

1.1 Our Results and Techniques 

We introduce the Sampled Pairwise Externality Compensator (SPEC ) mechanism, a non-monetary schedul-ing mechanism for our setting which is both efficient and gives optimal ideal utility guarantees. We develop it in two stages. First, we define Pairwise Externality Compensation (PEC ), a mechanism for our model us-ing exact externalities; its pairwise accounting scheme draws on ideas in Safronov [Saf18] and its dynamic development in the Guaranteed Utility Mechanism (GUM) of Csóka et al. [Csó+23]. Second, we obtain 

SPEC by replacing exact externalities with sampled estimates. Coupled simulations and local mixing make this computation efficient while preserving robust individual utility guarantees. In particular, we obtain the following utility guarantee for SPEC .

Thus, each agent can secure this expected-utility guarantee even if all other agents collude to harm it. The leading factor 𝜆 (𝛿, 𝑛,𝑇 ) is optimal: even a fully informed central planner cannot guarantee every agent a larger fraction of ideal utility uniformly over value distributions. Our mechanism attains this factor up to an additive loss of e𝑂 (√𝑛𝑇 ) in total utility, which is sublinear in 𝑇 for fixed 𝑛 and 𝛿 > 0. We focus on the

Why persistent jobs create a computational challenge: When 0 < 𝛿 < 1, allocating the server changes both current utility and future competition. Serving one agent leaves other agents’ jobs waiting, changing their future queues and service opportunities. An agent’s report can therefore affect other agents over many subsequent periods. Our mechanism proposes a simple allocation rule that tracks these effects via pairwise externality compensation. However, evaluating them directly requires reasoning about the evo-lution of the queues over the remaining horizon. Our challenge is to estimate these future effects efficiently while preserving utility guarantees against arbitrary reporting strategies. Now, let us give a brief overview of how our mechanism works. At each time 𝑡 , each agent makes a report of how many “high-valued” jobs they currently have. The principal gives access to an agent uni-formly at random among agents who report a nonzero number. One can show that if each agent uses the simple strategy of reporting the number of jobs in their queue of value in the top 1 /𝑛 -quantile of their value distribution, and processes the highest-valued job when given the opportunity, each agent obtains at least a 𝜆 (𝛿, 𝑛,𝑇 ) fraction of their ideal utility in expectation. This choice of threshold also simplifies the mechanism’s information requirements. A newly arriving job is high-valued with probability exactly 1 /𝑛 ,2independently across agents and periods. Under the prescribed strategy, the process of high-valued job counts depends only on 𝑛 , expiration probability 𝛿 , and allocation rule, rather than on the value distribu-tions F𝑖 . This means the principal can simulate the job-count process without knowing or learning the job value distributions; each agent only needs to identify its own highest-valued job when served. This reduc-tion also characterizes the optimal benchmark factor: under the target policy, 𝜆 (𝛿, 𝑛,𝑇 )𝑇 is the expected number of high-valued jobs served, and the symmetric instance F𝑖 = Bern (1/𝑛 ) makes this tight — every positive-valued job has value 1, and no policy can serve more such jobs in expectation than a policy that serves one whenever one is available. Of course, agents need not follow this strategy. Nevertheless, PEC allows an agent to secure this guarantee, up to an e𝑂 (√𝑛𝑇 ) additive loss, even when other agents use arbitrary strategies . The relevant rules of PEC 

can be summarized through its pairwise virtual accounts: for each ordered pair of agents, the mechanism maintains a virtual account recording the cumulative externality of one agent’s reports on the other’s anticipated service. These accounts involve no monetary transfers. If an agent’s cumulative negative ex-ternality on another agent falls below a prescribed threshold, the former is temporarily required to report zero current jobs. Under the prescribed strategy, the externality increments have conditional mean zero, allowing concentration bounds to control the probability of such timeouts. An agent following the pre-scribed strategy avoids being timed out with high probability. Controlling both the externalities imposed by other agents and the loss from these timeouts yields the expected-utility guarantee in Theorem 1.1, regardless of the other agents’ strategies. The prescribed strategy is simple to implement: an agent reports the number of jobs in its queue whose values lie in the top 1 /𝑛 quantile of its own value distribution, and serves its highest-valued job when selected. Securing the guarantee requires neither observing other agents’ reports nor predicting their future behavior. In particular, the guarantee does not depend on other agents following the prescribed strategy or on play converging to an equilibrium. While participating in the PEC mechanism is simple from the perspective of the agents, the principal has a more difficult task. In particular, PEC requires the principal to compute the expected externality imposed on each other agent, which requires evaluating the effect of an agent’s report for the rest of the horizon. The technically challenging part of our work is in showing how coupled simulations and local mixing can be used to estimate these efficiently while preserving the utility guarantee. This leads to the SPEC 

mechanism, with the following runtime guarantee. 

Theorem 1.2 (Second part of Theorem 4.3, rephrased) . For fixed 𝛿 > 0, SPEC runs in 𝑂 (𝑛 2 log 𝑇 ) time per period in the worst case, 𝑂 (𝑛 2 log log 𝑇 ) in expectation, and 𝑂 (𝑛 2) amortized in expectation. These bounds hold under arbitrary reporting strategies. 

In particular, the expected amortized computation per period is independent of the horizon 𝑇 , even though the externalities being estimated include effects on future allocations. 

Pairwise externality compensation and utility guarantees: To explain how we obtain this result, we first describe the pairwise externality accounting underlying the PEC mechanism. Given the reports so far, consider the expected number of high-valued jobs served for each agent over the horizon, assuming that all agents follow the prescribed strategy from then on; call these the anticipated payoffs . In each period, reports are considered sequentially: agent 𝑖 ’s externality on agent 𝑗 is the change in 𝑗 ’s anticipated payoff when 𝑖 ’s report is incorporated. The mechanism records these externalities in pairwise virtual accounts. If an agent’s cumulative externality on any other agent goes below a threshold, the former is temporarily required to report zero. The core idea from Csóka et al. [Csó+23] is that this accounting can protect an agent against the effects of other agents’ reports. In our setting, when an agent follows the prescribed strategy, its reports have zero expected externality conditional on the preceding history. Concentration bounds then show that it 3rarely reaches a virtual debt limit. At the same time, the limits restrict the cumulative negative externalities imposed on it by other agents. Together, these observations yield the robust utility guarantee; we give the formal argument in Section 3. 

Efficient estimation through coupling and local mixing: It is not obvious how the principal could run this mechanism efficiently. In particular, the anticipated payoffs count the expected number of high-valued jobs served over the entire horizon, and when an agent 𝑖 makes a report in a given period, their report affects other agents’ opportunities in future periods as well. Computing these anticipated payoffs directly at every timestep could therefore be expensive. The key idea that allows us to obtain our efficient algorithm is that, at each timestep, the mechanism only needs estimates of externalities (i.e., changes in anticipated payoffs) rather than the anticipated payoffs themselves. We estimate these differences using coupled simulations. Specifically, when agent 𝑖 makes a report, to estimate its externality on agent 𝑗 , we couple two simulated versions of the future process. The first incorporates 𝑖 ’s actual report in the current period; the second replaces it with a report sampled according to the prescribed strategy. In both versions, we assume agents follow the prescribed strategy in future periods. We maximally couple the two chains (i.e., use the same randomness wherever possible) and stop simulating once they sync (i.e., have the same state), since their subsequent service outcomes are henceforth the same. The difference in the number of high-valued jobs served for agent 𝑗 in the two simulations is thus an unbiased estimate of the externality. We show these two Markov chains sync in time 𝑂 (log 𝑇 ) in expectation, giving us an 𝑂 𝑛 (log 𝑇 ) expected runtime for this basic estimator. To obtain the improved runtimes as in Theorem 1.2, we observe that the 𝑂 (log 𝑇 ) bound is pessimistic for queue sizes typically reported by agents following the prescribed strategy. We therefore add per-period and cumulative caps on reported queue lengths. These caps are unlikely to affect an agent following the prescribed strategy, but prevent arbitrary reports from making the simulations expensive. We also stop each simulation after a prescribed number of timesteps. This truncation makes the estimator slightly biased; we bound the resulting error and show that it preserves the utility guarantee up to the stated additive loss. Together, the coupling bound and these additional rules yield the improved runtimes even when agents report arbitrarily. Finally, we believe that this approach extends beyond our specific queuing model. As demonstrated by Csóka et al. [Csó+23], pairwise externality compensation provides a way to protect individual util-ity in dynamic allocation problems; however its implementation requires accounting for the future effects of reports. Our results suggest that these effects can be estimated efficiently in other Markovian settings where the prescribed process can be simulated and local mixing makes coupled trajectories agree quickly. This offers a route to making similar robust guarantees computationally accessible in a broader range of non-monetary allocation problems. 

1.2 Related Work 

Non-Monetary Repeated Resource Allocation: Prior work has investigated designing mechanisms in our setting in the special case when 𝛿 = 1. The problem was first introduced by Guo, Conitzer, and Reeves [GCR09]. Subsequent work [Cav14; GBI21a; JS07] studied repeated non-monetary allocation through linked decisions; in particular, Gorokh, Banerjee, and Iyer [GBI21a] gave a general technique to convert the efficiency guarantee of any monetary mechanism using a non-monetary mechanism up to a sublin-ear error. However, unlike our work, these works assume the principal has full knowledge of the value distributions. A more recent line studies distribution-agnostic mechanisms with agent-specific guarantees relative to the ideal utility benchmark, introduced by Gorokh, Banerjee, and Iyer [GBI21b]. For requests that must be served immediately (i.e., 𝛿 = 1 in our model), a sequence of works [GBI21b; Lin+25; Lin+26b] obtain 4progressively stronger worst-case guarantees that hold regardless of other agents’ behavior. Lin et al. [Lin+26a] obtain the optimal worst-case fraction at equilibrium, together with a weaker guarantee against arbitrary behavior by other agents. Beyond worst-case value distributions, Onyeze et al. [Ony+25] study equilibrium guarantees. Finally, recent work [Csó25; Csó26] on so-called ‘fair-floor guarantees’ implies the optimal worst-case fraction of ideal utility when 𝛿 = 1; we discuss these results and their relationship to our mechanism below. A related form of intertemporal demand arises when agents require the resource for several consecutive periods. Banerjee, Fikioris, and Tardos [BFT23] and Fikioris, Banerjee, and Tardos [FBT25] study such reusable-resource settings and obtain robust guarantees relative to ideal utility. This source of temporal dependence differs from ours: their requests can occupy the resource for multiple periods, whereas our jobs require one period of service but may wait in a queue before being served or expiring. 

Pairwise Externality Compensation and Guaranteed Utility: Our mechanism builds on the general Guaranteed Utility Mechanism (GUM) of Csóka et al. [Csó+23], which combines techniques from Safronov [Saf18] and Gorokh, Banerjee, and Iyer [GBI21a] to build non-monetary mechanisms for dynamic settings. Pairwise externality compensation accounts for the effects of one agent’s reports on another agent’s antici-pated payoff. Combined with techniques for replacing monetary transfers by artificial currencies [GBI21a], this yields non-monetary mechanisms with individual utility guarantees. Csóka, Pongrácz, and Rodivilov [CPR26] surveys guaranteed utility equilibria and their applications; these ideas have also found use in auction design [JST26]. In the immediate-expiration setting, Csóka [Csó25] uses a prior-free version of the GUM framework to get robust guarantees relative to a new fair-floor benchmark; Csóka [Csó26] obtains similar guarantees through a repeated virtual first-price auction. The fair-floor benchmark is more complicated to define, but it is at least a 𝜆 (1, 𝑛,𝑇 ) fraction of the ideal utility. Consequently, these results already imply the optimal worst-case fraction of ideal utility when 𝛿 = 1, up to a sublinear additive loss, regardless of other agents’ behavior. Our contribution is to characterize the optimal fraction of ideal utility with persistent jobs and to attain it through computationally efficient sampled compensation. Persistence makes a report affect other agents’ service opportunities over many future periods, which makes the externalities required by PEC complex. Rather than evaluating these effects exactly, we estimate them through coupled simulations of the high-valued job-count process. This process can be simulated without knowing agents’ value distributions, and local mixing allows the simulations to stop once their states agree. Controlling sampling fluctuations and truncation bias, together with report caps that rarely affect the prescribed strategy, preserves the robust utility guarantee while yielding 𝑂 (𝑛 2) expected amortized computation per period for fixed 𝛿 > 0. Each agent secures its guarantee through a simple strategy based on reporting high-valued job counts, without requiring other agents to follow an equilibrium strategy. 

Strategic Queues, Decentralized Learning, and Fair Sharing: There is a long literature on each of the classical topics from learning in queuing systems, dynamic matching with abandonment and fair sharing. Work on learning in queuing systems, such as [Abe+26; BSV23; FLW24; FHL22; GT23; Kri+16; Kri+21; SBP21] considers outcomes of no-regret learning and clarifies how coordination, information, and learn-ing affect stability and service capacity. Our objective is instead to guarantee each agent utility from heterogeneous, privately valued jobs that may expire. Queueing and expiration also arise in dynamic matching. AmaniHamedani, Aouad, and Saberi [AAS25] study a continuous-time model in which suppliers wait in queues and may abandon, while customers must be matched on arrival by centralized system, highlighting the value of adapting decisions to queue states when opportunities may expire. In contrast, we design a non-monetary mechanism for agents with private values and queue states, with robust individual utility guarantees. 5There is also a long literature of online mechanisms that aim to provide fair shares for all agents. For example recent work of Salem, Iosifidis, and Neglia [SIN23] studies repeated allocation decisions when utilities vary over time and the goal is to satisfy 𝛼 -fairness in the long run. In this paper, we consider ideal utility, an individual fair share benchmark, and develop a mechanism that guarantees each player a fraction of this benchmark independently of the behavior of other players.

# 3 Pairwise Externality Compensations and Utility Guarantees 

We now provide a brief summary of the steps we follow in the rest of the paper to prove our main result. We first define the pairwise virtual externality of an agent’s report as the change it causes in another agent’s anticipated future utility (Section 3.2). We then formally define the PEC mechanism (Algorithm 1 in Section 3.3), and prove that under this mechanism, agents have a strategy that guarantees them a worst-case optimal fraction of their ideal utility. This guarantee requires a 𝑂 (polylog (𝑇 )) bound on the magnitude of each pairwise externality, to control the increments of the virtual-debt martingales and thus ensure an honest agent is rarely timed out; a priori, it is unclear if this is bound holds. In Section 3.4 we show that the externalities of such individual reports are bounded by a term that grows logarithmically with 𝑇 . To do so, we couple two variants of our queuing process: one incorporates the agent’s report at the current period, while the other samples that report from the target-policy transition kernel. We show that the two processes sync after 𝑂 (log 𝑇 ) periods in expectation, yielding the externality bound. The above coupling turns out to be critical for our subsequent results. In particular, in Section 4, we use this coupling to construct a computationally efficient, slightly biased estimator of each pairwise externality (Algorithm 2). 3.3 The PEC Mechanism and its Guaranteed Utility Property 

We now formally describe our PEC mechanism, which adapts the transfer-free version of the Guaran-teed Utility Mechanism (GUM) of Csóka et al. [Csó+23] to our queueing setting. # 4 Efficiently Computing the Externalities 

It is not clear how to efficiently implement Algorithm 1 because we have not given an algorithm to compute the externalities 𝛾 𝑖 →𝑗 [𝑡 ]. In this section, we first give a mechanism that efficiently computes estimators

We then show how to improve the algorithm’s runtime by modifying the mechanism slightly. 

4.1 Computational Model 

In this paper, we assume a standard computational model (e.g., Word RAM with randomization) augmented with a sampling oracle that can draw from the distribution Binom (𝜃, 𝛿 ) for 1 ≤ 𝜃 ≤ 2𝑇 in 𝑂 (1) time. 15 4.2 Basic Algorithm 

The proof of Lemma 3.8 already gives an algorithm to compute an unbiased estimator of 𝛾 𝑗 →𝑖 [𝑡 0]: we couple two simulated instances of the high-valued jobs stochastic process starting at update (𝑡 0, 𝑗 ) until the two instances sync, where one of the processes starts with a random state and the other starts with a state with the report b𝜃 𝑗 [𝑡 0], and we output the difference in the number of high-valued jobs that agent 𝑖 

serves between the two processes as the estimator b𝛾 𝑗 →𝑖 [𝑡 0]. This estimator is unbiased by the definition of externality. By the proof of Lemma 3.8, the two coupled processes will sync in expected 𝑂 (log 𝑇 ) timesteps. Since simulating each timestep in each process takes 𝑂 (𝑛 ) computational time since there are 𝑛 updates per timestep, computing the estimator in this fashion takes 𝑂 (𝑛 log 𝑇 ) expected computational time. # C A Lemma for the Deferred Proofs: Converting Guarantees on the Number of High-Valued Jobs Served into Utility Guarantees 

Our main tool to give lower bounds on the utility of agents is to give lower bounds on the number of high-valued jobs served from that agent. Converting lower bounds on the number of high-valued jobs served into a lower bound on the utility is relatively straightforward if the agent served a random high-valued job each time they are granted access to the server. However, in our results, agents instead serve the highest-valued job each time they are granted access. Intuitively, this can only be better than serving a random high-valued job. # G AI and LLM Usage Disclosure 

We used the LLMs Google Gemini in the Google Antigravity application and OpenAI ChatGPT in the OpenAI Codex extension in Visual Studio Code in the process of developing some of the techniques in this paper. We used the ChatGPT 6 Astra (medium) to fill in routine mathematical details and computations and rewrote its proofs to be more stylistically in line with our writing. After writing the paper, we used ChatGPT 6 Astra (medium) to check for typos and mathematical errors. Only very minor errors were found and the corrections needed were small. Beyond checking for errors and filling in routine mathematical details, our usage of AI and LLMs was limited to developing the computational aspects of the mechanism. We developed all the modelling details and results of this paper, ignoring computational concerns, without any AI or LLM use. In particular, we came up with the general idea of the paper, the specific model, the idea to use the ideal utility benchmark, and the idea to use the Guaranteed Utility Mechanism all without any AI or LLM use. As for the computational aspects of our paper, almost all high-level ideas came from us with the LLMs only helping to speed up the process of filling in technical details and giving first drafts of formal proofs. Specifically, our research process to come up with first drafts of formal proofs can be summarized as follows. 1. We proposed to the Gemini 3.1 Pro (High) model our general idea of simulating the future timesteps of the mechanism at each GUM update until the Markov chain mixes many times to efficiently compute the externality payments. Gemini 3.1 Pro formalized this idea as simulating two coupled Markov chains until they sync and wrote initial drafts of proofs. 2. With the help of the ChatGPT 5.6 Luna (High) model, we spotted multiple errors. We asked Gemini to fix its errors by following the following multi-agent setup with two nested loops. In the inner loop, the main Gemini agent would fix its errors and have two “mathematical reviewer” subagents review its work and find errors repeatedly until both “mathematical reviewer” subagents agreed there were no more errors. In the outer loop, a “writing reviewer” subagent would review the proof writing quality and comment on issues. Pseudocode for this multi-agent setup is given in Algorithm 5. We repeated this multi-agent setup a few times, pointing out errors along the way that both we and independent ChatGPT 5.6 Luna (High) and ChatGPT 5.6 Luna (Very High) chats found. In this way, we quickly wrote an initial draft of our mechanism that is close to the initial mechanism that we presented with the e𝑂 𝑛 (√𝑇 ) utility error bound and e𝑂 𝑛 (log 𝑇 ) runtime at each step. Throughout this process, the LLMs also found that doing multiple simulations at each step is not helpful.
