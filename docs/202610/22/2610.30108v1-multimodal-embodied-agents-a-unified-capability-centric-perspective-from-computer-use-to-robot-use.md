## 摘要
多模态智能体（MMAs）通过推理、记忆、工具和反馈维持交互，最典型地表现为计算机使用智能体；而机器人系统（RSs）则在物理动力学下耦合感知与执行。我们将多模态具身智能体（MMEAs）定义为将多模态任务推理与物理行动相结合、并根据由此产生的反馈修正决策的目标导向系统。这引出一个核心问题：当多模态智能体从计算机使用转向机器人使用时，会发生什么变化？我们提出 PAPAV，一个统一的能力中心框架，包含五种反复出现的功能：感知当前状态、预判行动效果、规划可行路线、通过接口或身体执行、验证结果。这些能力按功能而非架构定义，使 PAPAV 能够识别三者的共同点，并将 MMEAs 与 MMAs 和 RSs 进行比较。从部分可观测性到不可验证结果，五项物理约束使得可预先固定的选择更少，纠错空间也更小。在 64 个基准中，显式评估主要集中在“执行”；仅 5 个评估“预判”，3 个评估“验证”，二者在很大程度上被任务成功率所掩盖。这些约束也构成了我们所识别的开放挑战。因此，PAPAV 为设计可靠的物理智能体以及衡量全部五种能力而非仅任务成功率的进展提供了共同基础。

## Abstract
Multimodal agents (MMAs) sustain interaction through reasoning, memory, tools, and feedback, most visibly as computer-use agents, while robotic systems (RSs) couple sensing and actuation under physical dynamics. We define multimodal embodied agents (MMEAs) as goal-directed systems that couple multimodal task reasoning with physical action and revise decisions from the resulting feedback. This raises a central question: what changes when a multimodal agent moves from computer-use to robot-use? We introduce PAPAV, a unified capability-centric framework of five recurring functions: Perceive the current state, Anticipate action effects, Plan a feasible course, Act through an interface or body, and Verify the outcome. Defined by function rather than architecture, these capabilities let PAPAV identify what all three share and then compare MMEAs with MMAs and with RSs. Five physical constraints, from partial observability to unverifiable outcomes, leave fewer choices fixed in advance and less room to reverse errors. Across 64 benchmarks, explicit evaluation centers on Act; only 5 assess Anticipate and 3 assess Verify, leaving both largely hidden behind task success. These constraints also frame the open challenges we identify. PAPAV therefore provides a common basis for designing reliable physical agents and measuring progress across all five capabilities rather than task success alone.

# 论文总结：Multimodal Embodied Agents: A Unified Capability-centric Perspective from Computer-Use to Robot-Use

## 1. 核心问题与研究动机

- **背景**：多模态智能体（MMAs）已从一次性生成发展为可长期交互、调用工具、依据反馈修正决策的系统，典型形态是浏览器/桌面/手机上的 computer-use agent；机器人系统（RSs）则沿另一条路径，把基础模型与通用策略接到物理动作上。两条传统各有积累：机器人学擅长在物理动力学下闭环，智能体研究擅长维持长程交互。
- **核心问题**：**当多模态智能体从“计算机使用”迁移到“机器人使用”时，究竟什么发生了变化？**
- **问题根源**：现有综述的 taxonomy 仍按各自学科划分——computer-use 综述偏重计算架构与数字交互，具身 AI/VLA 综述偏重物理任务与执行。虽有若干综述同时覆盖两端，但“都覆盖”不等于“建立类比”：现有分类只描述各自设定内的系统，未揭示同一功能在行动获得物理后果后如何改变。
- **关键观察**：计算机使用智能体可依赖软件提供的结构化状态与直接反馈，传统机器人系统可依赖为已知工况选定的约束；而开放式物理交互二者皆不充分——同一循环更不可预测、更不容错，更多决策被迫移入交互过程本身。
- **概念界定**：论文将 **MMEA（多模态具身智能体）** 定义为“用多模态证据指导物理行动、并用行动反馈修正后续决策”的目标导向系统，并强调 MMEA 是 MMA 与 RS 的交集而非简单并集。

## 2. 方法论：PAPAV 能力中心框架

### 2.1 核心思想

- 以**功能而非架构**定义能力：同一模型可承担多种功能，同一功能也可分散在多个模型/工具中。点击、技能调用、机器人轨迹形式不同，但都可在同一“任务循环”坐标下比较其贡献。
- 比较单元是**任务级循环（task-level loop）**：一次点击与一个控制 tick 不可比，但一个任务步可比。这使数字与物理两种设定落在同一时间尺度上。

### 2.2 五项能力（PAPAV）

| 能力 | 功能定义 | 关键输出 |
|---|---|---|
| **Perceive** | 从多模态证据形成任务信念 | 任务相关状态表示、带置信度/来源/新鲜度的“合格信念” |
| **Anticipate** | 估计候选干预引起的状态变化 | 动作条件化的未来状态/风险/进度预测 |
| **Plan** | 在任务、环境、具身约束下选出可行路线 | 授权的行动课程、子目标、依赖与适用约束 |
| **Act** | 把语义意图落地为接口/身体可执行的干预 | 环境兼容的动作规格、执行进度 |
| **Verify** | 把行动后证据转为判定 | 继续/成功/重试/重规划/失败的裁决 |

- 特别区分了两个常被折叠进“观察–决策–行动”循环的边界：**Anticipate** 问“候选动作可能造成什么”（在 Plan 之前），**Verify** 问“行动后证据是否支持预期结果”（而非仅记录又一次观察）。
- **Memory 与 orchestration 不列为第六能力**，而被称作 **agentic harness**（协调基底），负责跨时间连接五项功能。

### 2.3 形式化流程（公式的文字说明）

- **任务循环（式1）**：给定交互历史 $h_k$ 与目标 $g$，Perceive 产生任务信念 $b_k$；Anticipate 产生预测效应 $\Delta b_k$；Plan 产生意图课程 $p_k$；Act 经域 $d$ 的转移/观测模型 $(T_d, O_d)$ 产生动作 $a_k$、执行进度 $\rho_k$ 与新观测 $o_{k+1}$；Verify 产生裁决 $v_k$，并回馈至下一步。
- **MMEA 判定三条件**（用于整系统归类，而非能力归类）：
  1. **持续具身任务循环**：任务相关状态跨多轮物理执行保持，所选动作能在物理环境产生可观测变化；
  2. **任务级能力回流**：每项声称的 PAPAV 能力都有可记录的输出，且能影响循环内后续的任务级决策；
  3. **具身约束承诺**：任务决策显式考虑物理可行性、执行时序与控制约束。
  证据缺失记为“不确定”，明确缺失则排除出 MMEA 类。
- **可行动作集（式2）**：给定信念 $b_k$ 与具身 $e$，可行动作需同时满足几何可行性 $\Gamma_{geo}$、动力学可行性 $\Gamma_{dyn}$、安全约束 $\Gamma_{safe}$（三者均需 ≤ 0），且执行时间 $\tau_{exec}(a,e) \le \tau_{max}$（当前任务步的时间预算）。

### 2.4 五项物理约束

部分可观测性、有限可模拟性、不可逆性、实时耦合、不可验证结果——它们共同使“可预先固定的选择更少、纠错空间更小”。

### 2.5 提出的可观测性判据（分析性字段，非既有系统已实现的接口）

- Perceive：**qualified belief**（信念 + 置信度 + 来源 + 采集条件 + 新鲜度）；
- Anticipate：**applicability envelope**（预测变量与时间跨度、已测工况、越界检测信号）；
- Act：**bidirectional execution contract**（下行：能力、目标、参数、前置条件、可中断点；上行：控制器状态、状态变化估计、进度、终止、故障、观测时间）；
- Verify：**evidential-dependency profile**（证据来源、与执行系统的依赖、相关性失败）。

## 6. 主要结论与发现

- **显式评估高度集中于 Act**：10/10（100%）MMEA、16/23（70%）MMA、29/31（94%）RS。
- **Perceive** 显式覆盖：7/10（70%）MMEA、10/23（43%）MMA、10/31（32%）RS。
- **Plan 呈现最清晰的家族差异**：7/10（70%）MMEA 显式评估，其余 3/10 为隐式；MMA 与 RS 中**没有任何显式评估案例**（MMA 16/23 隐式、7/23 未评估；RS 13/31 隐式、18/31 未评估）。作者强调这反映**协议设计**而非系统能力。
- **Anticipate 与 Verify 严重欠评估**：仅 **5/64（8%）** 显式评估 Anticipate，仅 **3/64（5%）** 显式评估 Verify，二者大多被任务成功率掩盖。
- **过程诊断稀缺**：process-diagnostic 仅占 MMEA 4/10（40%）、MMA 4/23（17.39%）、RS 7/31（22.58%）；总体 24 outcome-only、25 outcome-augmented、15 process-diagnostic。
- **跨域趋同**：交互式评估在三个家族间日益相似（持久状态、多步交互、多模态反馈、协同动作）。
- **五项开放挑战（OC1–OC5）**：持久物理信念该记什么/忘什么；什么未来值得预测（决策相关性而非保真度）；何时应重规划（自适应承诺粒度）；不确定时该行动、观测还是求助；如何从验证中学习并避免错误累积。
- **总体主张**：可靠性取决于智能体能否维持信念、限定预测、授权承诺、保持执行可见、并在物理后果展开时核验结果；进展应按五项能力而非单一任务成功率衡量。

- **能力定义的“单标签”简化**：一个基准只归入一个家族、一项能力只给一个等级，可能掩盖同一基准内多能力耦合与时间分辨率差异（论文承认能力可在不同时间尺度上复现，但标注未体现）。
- **缺少系统级性能证据**：未比较任何具体 MMEA 系统在五项能力上的实测强弱，也未量化“能力覆盖度”与“任务成功率”之间的相关性。
- **提出的接口/字段均为规范性建议**：qualified belief、applicability envelope、双向执行契约等并非现有系统的既成属性，论文也明确承认这一点，因此其可操作性有待后续工作检验。
- **应用限制**：框架面向“有物理身体或物理后果”的闭环系统，对纯离线生成、纯理解类任务、以及强人在环（人选择每一步动作）的系统，其归类与评估意义有限；对多智能体协作场景只做了初步覆盖（PARTNR、RoCoBench、Habitat-MAS）。
- **文献时效与可核验性**：语料截止于 2026 年 9 月，且引用中包含大量同年预印本，部分条目尚难独立核验，可能影响覆盖计数的稳定性。
