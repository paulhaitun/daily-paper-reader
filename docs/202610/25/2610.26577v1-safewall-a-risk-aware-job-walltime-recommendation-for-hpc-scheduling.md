## 摘要
在高性能计算（HPC）中，用户必须为其作业提交资源需求，其中用户提供的墙钟时间是一个关键参数。然而，这些估计往往并不准确，因为用户倾向于高估墙钟时间，以避免调度器过早终止其作业。现有基于学习的墙钟时间预测工作主要关注最大化预测准确率，但此类预测用于墙钟时间推荐时本质上存在风险。具体而言，低估会导致作业在完成前被终止，从而造成进度损失和资源浪费。在本研究中，我们提出 SafeWall，一种新颖的推荐方法，通过引入显式的非负安全缓冲区来调整墙钟时间预测，以缓解低估风险。我们方法的核心是一个风险感知缓冲区，它根据单个用户的历史行为动态校准安全边际。当用户数据有限时，系统采用统计收缩使这些边际与全局基线对齐，从而确保稳健性。这形成了一种轻量级机制，可优化预测准确率与终止风险之间的权衡。SafeWall 是模块化的，适用于各种基于学习的预测模型。我们使用五个公开工作负载轨迹评估 SafeWall，其中包括来自 Argonne Leadership Computing Facility 的 4,392 节点 Theta 机器的全生命周期作业日志。在所有轨迹上，与无缓冲区的基础预测器相比，SafeWall 大幅降低了低估风险，同时保持了有竞争力的准确率。源代码公开于 https://github.com/SPEAR-UIC/JSSPP26-SafeWall。

## Abstract
In high-performance computing (HPC), users must submit resource requirements for their jobs, with user-supplied walltime being a critical parameter. However, these estimates are notoriously inaccurate, as users tend to overestimate walltime to prevent the scheduler from terminating their jobs prematurely. While existing work on learning-based walltime prediction primarily focuses on maximizing prediction accuracy, such predictions are inherently risky for walltime recommendations. Specifically, underestimation leads to job termination before completion, resulting in lost progress and wasted resources. In this study, we present SafeWall, a novel recommendation method that adjusts walltime predictions by incorporating an explicit, nonnegative safety buffer to mitigate underestimation risk. The core of our approach is a risk-aware buffer that dynamically calibrates safety margins based on individual user's historical behavior. When user data is limited, the system employs statistical shrinkage to align these margins with a global baseline, ensuring robustness. This yields a lightweight mechanism that optimizes the trade-off between prediction accuracy and termination risk. SafeWall is modular and applicable to various learning-based prediction models. We evaluate SafeWall using five public workload traces, including the full-lifetime job log from the 4,392-node Theta machine at the Argonne Leadership Computing Facility. Across all traces, SafeWall substantially reduces underestimation risk compared to the unbuffered base predictors, while preserving competitive accuracy. The source code is publicly available at https://github.com/SPEAR-UIC/JSSPP26-SafeWall.

# SafeWall：面向 HPC 调度的风险感知墙钟时间推荐 —— 论文结构化总结

## 1. 核心问题与研究动机

- **背景**：HPC 批调度器（尤其是回填 backfilling）依赖用户提交的 walltime 作为作业运行时长的上界。但用户为防作业被提前杀掉，普遍**高估** walltime（Theta 上运行时/请求时长中位数仅约 36.5%，MetaCentrum 更低至约 3.5%），造成保留资源浪费、回填机会减少。
- **核心矛盾**：现有学习型运行时预测研究几乎都以**最大化预测精度**为目标，使用对称损失（如平方误差）。在高度右偏的运行时分布下，对称损失训练出的强预测器仍有约 **47%–49% 的低估率（UR）**。
- **风险不对称性**：低估 → 作业在 walltime 上限被硬杀，已算进度全部丢失；高估 → 仅多占一点保留空隙。二者代价严重不对等。
- **论文主张**：walltime 推荐本质上是一个**单边风险控制问题**，不能只看 RMSE/MAE/R²，必须显式优化低估率。SafeWall 因此把"估计"与"安全"解耦，在任意预测器之上加一层非负、风险感知的缓冲。

## 2. 方法论

### 2.1 总体架构（两组件、模型无关）

- 组件一：**基础预测器** `ŷ_i = f(x_i)`，仅用调度器可见特征 + 轻量用户历史摘要。
- 组件二：**风险感知缓冲适配器**，输出非负安全边际 `b_i ≥ 0`，最终推荐 `ỹ_i = ŷ_i + b_i`。
- 关键性质：缓冲层只依赖历史残差，可包裹任意预测器（XGBoost、分位数 GBR、集成模型、Transformer 等），调高风险等级只需重算残差分位数，无需重训模型。

### 2.2 数据预处理

- 将 Theta 原始日志字段映射到 **Standard Workload Format (SWF)**（提交时间、等待时间、运行时、请求 walltime、节点数、退出状态、用户/项目 ID），提交时间归一化为相对秒数并按时间排序。
- **右删失处理**：运行时达到或超过请求 walltime 的作业视为右删失，将运行时标签**截断（cap）到 walltime**，避免无界超时值污染残差分布。

### 2.3 特征工程

- **滞后特征**：用户前一次、前两次作业运行时及其均值。
- **请求准确率**：`a_j = min(wall_j / y_j, y_j / wall_j) ∈ (0,1]`，并取用户级均值/最大值及最近 10 个作业的变体。
- **长程统计**：历史运行时的均值/最大值、近期均值/最大值、历史成功运行时的第 25 百分位。
- **防泄漏**：所有历史特征只使用严格早于当前作业的作业计算。
- **冷启动回退**：历史不足的用户直接回退到用户提交的 walltime（保守安全默认值）。最终 430,223 个作业中，367,477 个进入建模，62,746 个走回退。

### 2.4 基础预测器

- **XGBoost（平方损失）**：加性回归树集成，预测后做 `ŷ ← max(ŷ, 0)` 裁剪保证非负。
- **Quantile GBR（τ=0.95）**：最小化 pinball 损失，直接给出上条件分位数，作为"免缓冲"的对照方案。
- 超参：随机搜索 + 5 折交叉验证，平方损失模型选交叉验证 R² 最大者，分位数模型选分位数损失最小者，再在全训练集重训。

### 2.5 风险感知缓冲三步流程

- **第 1 步：全局误差缓冲**。在训练集上计算残差 `e_i = y_i − ŷ_i`，`e_i > 0` 即低估。给定目标低估率 `τ`（如 0.10），取正残差分布的 `1−τ` 分位数：
  `b_g(τ) = Q_{1−τ}({e_i : e_i > 0})`
  含义：该缓冲可覆盖约 `(1−τ)` 比例的历史低估情形，使未来 UR 近似稳定在 τ，且 τ 是显式的"松紧旋钮"。
- **第 2 步：用户级调整 + 统计收缩**。对用户 u 的正残差集合 `E_u`（样本数 `n_u`）计算 `b_u(τ) = Q_{1−τ}(E_u)`，再做凸组合收缩：
  `b̃_u(τ) = [n_u/(n_u+κ)]·b_u(τ) + [κ/(n_u+κ)]·b_g(τ)`，`κ = 10`
  - `n_u` 大 → 接近个性化；`n_u` 小 → 退化为全局基线；`n_u = 0` 时精确等于 `b_g(τ)`。
- **第 3 步：应用缓冲**：`ỹ_i = ŷ_i + max{0, b̃_{u_i}(τ)}`。
- **可选滚动窗口**：只用最近 W 个已完成作业计算 `b_u(τ)`，以应对分布漂移，但需额外调 W。

## 6. 主要结论与发现

- **高精度 ≠ 高安全**：Theta 上 XGBoost 的 R²=0.9835、对称精度 97.20%，但 UR 高达 **47.85%**；四个跨系统 trace 上无缓冲 UR 均落在 **47.9%–49.2%**，符合对称损失在偏态误差下的理论预期。
- **SafeWall 显著降低风险**：Theta 上 XGBoost+SafeWall 将 UR 从 47.85% 降至 **4.31%**，Quantile GBR 从 5.56% 降至 **3.46%**；跨系统 UR 降至 **4.92%–6.79%**，同时 R² 基本保持（Theta 上 0.9835→0.9834）。
- **优于朴素缓冲与外部强基线**：百分比缓冲虽把 UR 压到 1.06%，但 RMSE 飙至 1,808 s、精度跌至 82.83%；Oztop 框架复现可达 UR=3.06%，但 RMSE=18,505 s、MAE=14,733 s，而 SafeWall 在同等 UR 区间（3–4%）下 RMSE 仅约

…数百秒量级（具体数值见表 2），即在把 UR 压到与外部强基线相当水平的同时，RMSE/MAE 比 Oztop 框架低一个数量级以上。这说明**风险控制不必以牺牲预测质量为代价**，关键在于缓冲的构造方式（残差分位数 + 非负约束 + 用户收缩），而非缓冲的绝对大小。

- **风险–精度权衡是显式可调的**：与百分比/固定值缓冲"一刀切放大"不同，SafeWall 的缓冲量由残差分布决定，只对历史上被低估的作业类型补足，对本来就高估的作业几乎不加码。因此它能在 UR 与 RMSE/精度之间沿一条更优的曲线移动，而不是像 ×1.2 缓冲那样以精度崩塌换取低 UR。

- **用户级异质性真实存在但需收缩保护**：训练–测试期用户平均残差存在持续性（稳定低估型用户与稳定高估型用户可区分），支持"个性化缓冲"的动机；但单个用户样本量差异极大，直接采用用户分位数会在小样本用户上剧烈波动，这正是 κ=10 收缩项的作用所在。

- **工作负载画像揭示风险来源**：运行时–规模联合分布显示大量作业集中在短时长区间且长尾显著，右偏分布正是对称损失下 UR 接近 50% 的结构性原因；不同系统（批调度 / 网格 / 容器）的分布形态差异明显，但 SafeWall 的相对收益在各系统上保持一致。

- **模型无关性得到初步验证**：同一缓冲层分别包裹 XGBoost 与 Quantile GBR 后，两者 UR 均收敛到 3%–4% 区间，且 Quantile GBR（本身已是 τ=0.95 的上分位预测）叠加缓冲后风险进一步下降，说明缓冲层可与不同风险偏好的基础预测器正交组合。

## 7. 局限性与开放问题

- **超参数未做敏感性分析**：τ 与 κ 固定为 0.10/10，缺少扫描曲线，用户无法据此为不同 SLA 等级（如"允许 5% 被杀"vs"绝不允许被杀"）选择参数。
- **滚动窗口机制未实证**：分布漂移是 HPC 负载的常态（新应用上线、队列策略调整），但窗口长度 W 的效果未评估。
- **个性化收益缺少直接消融**：全局缓冲 vs 用户收缩缓冲的 A/B 对照缺失，个性化贡献只能由异质性统计间接推断。
- **无系统级闭环验证**：全部为离线回放，未量化对回填成功率、平均排队时间、集群利用率的影响；而 walltime 收紧本身会改变调度器行为，存在反馈回路，离线指标无法捕捉。
- **无统计显著性检验与置信区间**，小幅度指标差异（如 4.31% vs 3.46%）的稳健性存疑。
- **删失处理采用硬截断**：把超时作业的运行时截到 walltime 会系统性低估这部分作业的真实需求，虽然删失率很低（Theta 0.1%），但在 KIT-FH2（6.6%）等删失率较高的 trace 上可能引入偏差；生存分析式处理是更严谨的替代方案。
- **冷启动用户占比不低**：Theta 上约 14.6% 的作业（62,746/430,223）走回退路径，这部分作业实际未获得任何预测收益，论文未单独报告该子集的指标。

## 8. 对实践的启示

- 对调度器运维方：walltime 推荐应作为**独立的策略层**而非预测模型的副产品，这样可以在不重训模型的前提下按业务需要调节风险档位。
- 对用户：系统给出的"推荐 walltime"应附带风险语义（如"约 90% 概率足够"），而非一个无解释的数字，这有助于改变用户"宁高勿低"的保守申报习惯。
- 对研究者：评价运行时预测器时应同时报告 UR，仅报 RMSE/R² 会系统性掩盖单边风险；在右偏分布下，高 R² 与高 UR 完全可以并存。

## 9. 总体评价

**贡献定位**：论文的核心贡献不在预测模型本身（用的是现成 XGBoost / GBR），而在于**问题重构**——把 walltime 推荐从"回归精度问题"重新定义为"单边风险控制问题"，并给出一个极简、模型无关、可解释的后处理方案。这一视角转换的实践价值高于其技术复杂度。

**优点**：方法简单可复现、计算开销低、可直接叠加在已有调度器预测模块之上；跨 5 个异构系统、3 种调度范式的验证覆盖面在同类工作中较为突出；与外部已发表框架的同划分复现对比提升了说服力；同时报告风险指标与传统精度指标，避免了单指标误导。

**不足**：实验的"广度"优于"深度"——超参敏感性、组件消融、统计显著性、系统级闭环影响均缺失，导致"τ 是可靠的风险旋钮"这一核心主张缺少定量支撑；模型无关性也仅在两棵树模型上验证。

**可信度判断**：主要结论（对称损失导致约 50% 低估率；残差分位数缓冲可将 UR 压至个位数且不显著损害精度）在方法逻辑上自洽，且跨系统一致，可信度较高；但具体数值层面的精细比较（各方法间 1–2 个百分点的差距）因缺少显著性检验而应谨慎解读。

**适用边界**：适用于作业运行时具有可学习结构、且用户历史可追踪的批/网格/容器调度场景；对首次提交、无历史、或运行时高度随机（如强交互式、检查点频繁重启）的作业，收益有限。
