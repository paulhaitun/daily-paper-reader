## 摘要
协同具身人工智能（CEAI）使多个物理智能体能够在动态环境中协同感知、推理和行动。有效通信对CEAI至关重要，然而CEAI智能体不仅需要交换大规模多模态观测数据，还需要在长时程内交换任务相关见解、意图和交互信息。本文将Token通信（TokCom）作为CEAI的原生智能接口进行研究，其中token既作为用于通信的紧凑语义载体，也作为生成式基础模型（GFM）的基本推理单元。我们首先讨论TokCom如何支持具身智能体之间的见解共享、意图对齐和交互控制。然后，我们提出一种由任务自适应通信协议驱动的TokCom辅助CEAI框架。该协议由紧凑码本、语法规则和上下文示例组成，指导基于GFM的收发机将消息蒸馏为紧凑token，并在无线传输后重建这些消息。一个关于协同物体运输的案例研究表明，所提出的TokCom框架在保持任务效率的同时显著降低了源载荷比特消耗，并在噪声信道下表现出鲁棒性。最后，我们概述了未来的研究方向。

## Abstract
Collaborative embodied artificial intelligence (CEAI) enables multiple physical agents to perceive, reason, and act cooperatively in dynamic environments. Effective communication is essential for CEAI, yet CEAI agents must exchange not only large multimodal observations but also task-relevant insights, intents, and interactive information over long horizons. This article investigates token communication (TokCom) as a native intelligence interface for CEAI, in which tokens serve jointly as compact semantic carriers for communication and fundamental inference units for generative foundation models (GFMs). We first discuss how TokCom supports insight sharing, intent alignment, and interactive control among embodied agents. We then propose a TokCom-assisted CEAI framework driven by a task-adaptive communication protocol. Comprising a compact codebook, syntax rules, and contextual examples, this protocol guides GFM-based transceivers to distill messages into compact tokens and reconstruct them after wireless transmission. A case study on collaborative object transport demonstrates that the proposed TokCom framework substantially reduces the source payload bit consumption while preserving task efficiency and showing robustness under noisy channels. Finally, we outline future research directions.

# 论文总结：Token通信辅助的协同具身人工智能

## 1. 核心问题与研究动机

- **背景**：协同具身人工智能（CEAI）指多个物理智能体在共享环境中分布式地感知、推理与行动，以完成共同目标。受限于部分可观测性与单体物理约束，通信成为智能体交换感知、对齐意图、协调行动的关键机制。
- **现有范式不足**：
  - **比特中心通信**：以可靠比特传输为目标，对装备密集传感器的具身智能体而言需传输海量原始数据，带宽与时延开销大；且存在“悬崖效应”，信道恶化时协作性能骤降。
  - **语义通信（SemCom）**：虽从数据保真转向语义保真，但系统通常针对预定义任务训练，神经权重与下游目标静态绑定，任务变化需重新训练，缺乏 CEAI 所需的通用性与适应性。
- **CEAI 的通信新需求**：
  - **多模态接地**：需跨模态对齐（如视觉→语言、语言→动作）。
  - **任务导向有效性**：应从 Shannon-Weaver 的“有效性”层面，以协作任务最终成败衡量通信价值，而非仅看比特错误率或语义保真度。
- **核心主张**：Token 通信（TokCom）中，token 同时充当**紧凑的多模态语义载体**与**生成式基础模型（GFM）的基本推理单元**，可作为一种“原生智能接口”，把通信有效性与协作任务成功直接对齐。

## 2. 方法论

### 2.1 核心思想
在 GFM 推理与无线传输之间插入一个**任务自适应协议层**，将面向推理的自然语言转译为紧凑、抗噪、可解释的“智能体语言”（协议 token），从而同时解决预训练 tokenizer 的两大低效问题：
- **序列级冗余与歧义**：自然语言含大量与执行无关的措辞，且同一意图可有多种表达，易造成接收端理解不一致。
- **词汇级开销**：通用 GFM 词表巨大（如 Gemma 4 约 26.2 万词表，每 token 需 ⌈log₂(262k)⌉=18 比特），对频繁多智能体通信而言开销过高。

### 2.2 TokCom 对 CEAI 的三层支撑
- **感知层——见解共享**：多模态见解表征（将视觉、听觉、LiDAR、触觉等统一为 token）；协作感知融合（发送端将局部观测蒸馏为与接收者相关的 token，接收端融合多源 token 与本地记忆）。
- **推理层——意图对齐**：动态目标同步（云端或选举协调者将全局目标编码为 token 序列）；异构感知的任务协调（交换能力约束与子任务计划以协商角色分配）。
- **执行层——交互控制**：原语指令生成（传输抽象动作原语，由接收端本地规划器实例化）；闭环反馈（交换跟踪偏差、接触状态、可行性、求助请求等轻量 token）。

### 2.3 框架组成

**(A) 任务自适应协议初始化**
协作任务开始前，由云端服务器或选举协调者用 GFM 生成共享协议并广播给所有智能体。协议依据任务信息、智能体能力与环境上下文生成，包含三要素：
- **紧凑码本**：仅保留任务相关语义原语（对象、动作、状态、空间概念），每个协议 token 分配紧凑 ID。若码本不超过 32 个 token，每 ID 仅需 ⌈log₂32⌉=5 比特（对比通用词表 18 比特），且每个 token 含义精确，抑制表达歧义。
- **语法规则**：规定 token 组合成合法序列的规则，统一构造与解释方式，并帮助接收端在噪声下识别被擦除或不可靠的 token。
- **上下文示例**：提供消息与编码序列的映射示例，使 GFM 通过上下文提示（in-context prompting）遵循协议，无需额外再训练。

**(B) 基于协议的编解码流程**（五阶段）
1. **消息生成**：智能体决定发送时先生成含意图的原始自然语言消息。
2. **协议化语义蒸馏（发送端）**：将原始消息与共享协议作为 GFM 编码器输入，约束输出仅含协议定义的码字，得到紧凑协议 token 序列。
3. **二进制映射**：将协议 token ID 映射为二进制载荷（文中采用固定长度映射，未用熵编码）。
4. **无线传输**：经信道编码、调制与解码（案例中使用 rate-1/2 卷积码、QPSK、软判决 Viterbi）。
5. **语义重建（接收端）**：GFM 解码器结合接收 token（可能被擦除/标记为不可靠）、共享协议与本地记忆（对话历史、动作历史）恢复语义，供后续推理与动作生成。

- **关键设计点**：协议可由同一 GFM、固定随机种子与相同采样配置在本地一致生成，故协议本身无需传输；协议初始化开销不计入比特消耗指标。

## 3. 实验设计

- **仿真平台/基准**：ThreeDWorld（TDW）object-transport benchmark。
- **场景**：多房间房屋布局，两个能力相同的具身智能体（自我中心 RGB-D 感知、自主导航、物体操作、消息传输），初始位置不同、视野部分可观测，需协作搜索目标物体并运送至指定目标点，可选使用容器提升效率。
- **任务规模**：共 24 个任务实例，含 12 个 food 场景与 12 个 stuff 场景。
- **感知处理假设**：按模块化设计将 RGB-D 观测经感知模块转为文本，并**假设该转换完美保留图像语义**；作者称可扩展至任意模态。
- **模型配置**：Gemma 4 31B Dense（instruction-tuned）作为纯文本 GFM 骨干，模型冻结、仅推理，不从头训练也不微调；协议初始化、编码、解码均通过 in-context prompting 与默认采样配置实现。
- **对比方法**：
  - **No Comm.**：智能体独立运行，无通信（非通信参照）。
  - **Conventional TokCom**：GFM 生成自然语言消息，直接用 Gemma 4 默认 tokenizer 分词并映射为二进制传输。
  - **Protocol-Guided TokCom（本文提出）**：初始化任务自适应协议，将消息蒸馏为协议 token 序列并在接收端重建。
- **评价指标**：
  - **Transport Steps (TS)**：将所有目标物运至目标点所需累计仿真步数（越少任务效率越高）。
  - **Bit Consumption (BC)**：信道编码前所有智能体间消息产生的源端载荷比特总数（不含信道编码冗余、包头与协议初始化开销）。
- **噪声评估**：AWGN 信道，两方案共用同一数字通信链；采用 token 擦除抽象，将信道解码后判定为不可靠的 token ID 替换为 `[MASKED]`；计算 token 错误率（TER，重建前被标记不可靠的协议 token ID 比例），并考察句子相似度与 TS 随 SNR 的变化。

- **实验组数概览**：
  - 主实验：24 个任务实例 × 3 种方案（No Comm.、Conventional TokCom、Protocol-Guided TokCom），分别在 food 与 stuff 两类任务上报告 TS 与 BC。

  - 一项初步消融/探索：不加共享协议、仅要求 GFM 压缩消息的试验，发现 TS 未可靠改善（说明协议的必要性）。
- **充分性评估**：
  - **优点**：任务类型分两类、指标兼顾任务效率与通信效率、噪声实验将通信质量与任务结果直接关联，逻辑闭环较好。
  - **不足**：
    - 仅单一 benchmark（TDW transport）、单一 GFM 骨干（Gemma 4 31B），缺少跨模型、跨任务的泛化验证。

## 6. 主要结论与发现

- **通信有效**：通信总体降低 TS，帮助智能体协调探索、避免重复搜索同一房间或争抢同一物体。相比 No Comm.，Conventional TokCom 平均在 food 任务降 **21.02%**、stuff 任务降 **16.44%** 的 TS。
- **协议保持任务效率**：Protocol-Guided TokCom 取得与 Conventional TokCom 相当的步数削减，说明任务自适应协议保留了协调关键语义。
- **显著降低通信开销**：
  - 每回合平均传输 token 数从 **476.08 降至 78.88**（降幅 **83.43%**）。
  - 码本仅约 22–28 个协议 token，每 ID 需 5 比特（对比通用 tokenizer 的 18 比特）。
  - 两因素叠加使总源载荷降至 Conventional TokCom 的约 **5%**，同时运输效率相当。
- **协议不可或缺**：无共享协议的“自由压缩”虽缩短文本，但因缺乏共同码本与语法，跨智能体可解释性差，未能可靠提升 TS。
- **噪声鲁棒性**：SNR 从 0 dB 升至 2 dB 时，TER 从 **0.60 骤降至 0.03**，TS 随之下降；SNR ≥ 2 dB 后平均 TS 趋于稳定并与无差错情形相当。说明**精确句子恢复并非必要**，只要协调关键语义可被推断即可。协议结构通过缩小搜索空间、结合语法与邻接 token 类型约束及本地记忆，提升了擦除恢复能力。
- **总体判断**：任务自适应协议引导的 TokCom 可在保持协作任务性能（含 token 擦除条件下）的同时大幅降低源载荷比特消耗。

## 7. 优点

- **概念清晰、定位准确**：将 token 的“语义载体”与“GFM 推理单元”双重角色统一，提出 TokCom 作为 CEAI 的原生智能接口，并从感知/推理/执行三层系统化阐述其作用。
- **问题诊断具体**：明确指出现有 GFM tokenizer 面向推理而非通信，从“序列级冗余与歧义”和“词汇级开销”两个层面量化了失配（如 18 比特/token 的具体数字）。
- **方法轻量实用**：协议生成、编码、解码全部通过 in-context prompting 实现，模型冻结、无需训练或微调，工程落地门槛低；协议可本地一致生成而无需传输，进一步节省带宽。
- **评价视角先进**：以“有效性层面”指标（任务完成步数）而非 token 恢复准确率评价通信，符合具身多智能体长时程协作的本质。
- **协议设计兼顾多重收益**：紧凑码本提升效率、精确语义抑制歧义、语法规则辅助噪声下纠错、示例支持免训练适配，一套机制同时服务效率、鲁棒性与可解释性。
- **实验对照设置较严谨**：共享同一通信链与调制编码方案，控制变量；并诚实报告了通信方案在少数场景反而步数更多的负面现象。
- **未来方向针对性强**：JSCC、动态协议更新、异构 GFM 互操作三点均直接对应文中暴露的短板。

## 8. 不足与局限

- **实验覆盖有限**：
  - 仅一个 benchmark（TDW object transport）、一类任务族（找物+运送）、两个同构智能体，未验证更复杂协作（如装配、救援）与更大规模智能体团队。
  - 仅用单一 GFM 骨干（Gemma 4 31B），未考察不同规模/架构模型对协议遵循能力的影响。
- **强假设削弱结论**：RGB-D 观测经感知模块“完美转文本”的假设回避了真实多模态 tokenization 的损失与跨模态对齐难题，使“多模态”主张的实证支撑不足。
- **基线不完备**：缺少与 SemCom、任务导向通信、学习式多智能体通信等主流方法的对比，难以判断相对优势的幅度。
- **统计严谨性不足**：24 个实例、未见重复实验的方差/置信区间/显著性检验；作者自承部分场景结果受 GFM 采样随机性影响，结论稳健性有待加强。
- **开销核算偏乐观**：协议初始化开销被排除在 BC 之外，且依赖“同模型、同种子、同配置可本地生成一致协议”的理想前提；作者也承认该开销对短任务或频繁重生成协议的场景会更显著。
- **信道模型简化**：仅 AWGN + token 擦除抽象，未涉及衰落、多径、真实分组丢失；作者明确指出未检测的 token 替换错误比擦除更具挑战，而实验未覆盖。
- **协议静态性**：协议在任务开始时一次性生成，任务中若发现未预期的新对象则无法处理；动态协议更新仅作为未来方向提出，未做验证。
- **异构性未验证**：框架假设各智能体使用兼容的 GFM 实现，不同架构、训练流程或量化方案下的语义一致性与互操作性均未测试。
- **应用限制**：依赖较强的中心化协调（云端或选举协调者生成协议）与 GFM 推理算力，在

……在算力与能耗受限的小型机器人、无人机集群等平台上部署门槛较高；中心化协调者亦可能在通信中断、节点失效或对抗环境下成为单点瓶颈，去中心化的协议协商机制文中尚未讨论。

## 9. 启示与可复现性

- **对 CEAI 通信设计的启示**：
  - 通信指标应从“比特保真”“语义保真”进一步上移到“任务有效性”，本文用运输步数（TS）与载荷比特（BC）的联合刻画提供了一个可操作的度量范式。
  - token 作为“语义载体 + 推理单元”的双重身份，提示未来通信栈可在 GFM 推理层与物理层之间显式设置**可协商的中间表示层**，而非把自然语言直接交给通用 tokenizer。
  - “协议即先验”的思路具有一般性：结构化码本与语法在低 SNR 下等效于一种**语义级信道编码**，可与 JSCC、信道编码联合优化，而非彼此独立设计。
  - 免训练、纯 in-context 的适配路径说明，基础模型的能力可以被“提示工程化”地复用于通信协议定制，降低跨任务重新训练的成本。
- **可复现性评估**：
  - **较好的一面**：benchmark（TDW object transport）、骨干模型（Gemma 4 31B Dense, instruction-tuned）、信道编码与调制参数（rate-1/2 卷积码、QPSK、软判决 Viterbi）、指标定义与噪声抽象（token 擦除、`[MASKED]`）均描述得较为具体，原则上可复现主实验趋势。
  - **不足的一面**：协议生成依赖采样配置与随机种子，未给出提示模板全文与码本示例；RGB-D→文本的感知模块细节缺失；“完美语义保留”的实现方式无法核验；24 个任务实例的具体划分与随机化方式未说明。这些都会影响第三方精确复现。
- **潜在应用场景**：多机器人仓储拣选与巡检、车路协同与编队、灾后搜救中的异构机器人协作、人机混合团队的指令对齐；在带宽受限（如水下、地下、强干扰）环境下，紧凑协议 token 的价值可能比本文 AWGN 设定更突出。
- **值得跟进的研究点**：
  1. 协议的**在线演化**：任务中发现新对象/新失败模式时的协议增量更新与版本一致性维护。
  2. **异构 GFM 互操作**：不同架构、规模、量化方案模型间的协议语义漂移与对齐机制。
  3. **端到端多模态**：以真实视觉/点云 tokenizer 替代“完美转文本”假设，检验语义损失对协作的影响。
  4. **更完备的基线**：与 SemCom、任务导向通信、学习式多智能体通信（如基于 MARL 的离散消息学习）直接对比。
  5. **真实信道与错误类型**：衰落、分组丢失、未检测的 token 替换错误，以及协议层与信道编码的联合设计。
  6. **开销摊销与系统级核算**：把协议初始化、GFM 推理能耗纳入端到端成本模型，评估其在短任务/高频重协商场景下的经济性。
  7. **安全与鲁棒性**：协议被窃听、篡改或投毒时的风险，以及协调者失效下的降级策略。

## 10. 总体评价

本文的贡献主要在于**问题定位与概念框架**：它准确指出通用 GFM tokenizer 与具身多智能体通信需求之间的结构性错配（序列冗余、词汇开销、任务绑定），并提出以“任务自适应协议 + 协议化语义蒸馏”作为轻量解法，把通信评价锚定在协作任务成败上。方法实现门槛低（模型冻结、纯提示驱动）、协议无需传输、码本紧凑，这些设计在工程上具有吸引力。

但实证层面仍属**概念验证性质**：单一 benchmark、单一模型、每类 12 个实例、无方差与显著性报告、缺少主流通信基线对比、以及“完美感知转文本”的强假设，使其结论更适合表述为“在该受控设定下方向可行、收益显著”，而非“已证明具有广泛泛化优势”。尤其是 83% 的 token 削减与约 5% 的载荷比例这两个亮眼数字，其可比性受协议初始化开销被排除、码本规模与任务复杂度强相关等因素影响，需在更复杂任务中重新校准。

综合而言，本文为 CEAI 的通信层提供了一个有价值的设计视角与可复用的实验骨架，其提出的三层支撑（感知/推理/执行）与协议三要素（码本/语法/示例）具备较好的可扩展性；后续工作若能在异构性、动态协议、真实多模态与统计严谨性上补强，该范式的说服力将显著提升。
