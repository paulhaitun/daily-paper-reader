## 摘要
我们提出 ASENA，一种具身智能体系统，将通用编程智能体与机器人感知、计算、监督执行和持久经验相连接。智能体能够编写并执行程序、检查记录的结果、修复故障，并在保持模型权重不变的情况下复用笔记和可执行技能。我们进一步提出 ASENA-VLN，一种 4B 单目导航策略，作为该可编程系统中的可选工具。ASENA-VLN 使用共享的视觉-语言解码器，为长程路线和短时域行为预测机体坐标系轨迹；该解码器在路线指令、视觉问答以及一个新构建的、由几何推导得到的原子导航任务数据集上训练。作为独立策略，ASENA-VLN 在 R2R 上达到 68.7%、在 RxR 上达到 70.2% 的最先进成功率。当与编程智能体集成时，学习到的导航在两项智能体基准上使 ASENA 的成功率提升 11 个百分点，同时减少执行时间。通过持久工作区演化与模拟器反馈，对重复出现的 100 任务子集进行十轮处理，进一步将 R2R 上的成功率从 72% 提升至 98%，将 RxR 上的成功率从 65% 提升至 89%。在具身问答任务上，ASENA 以更少的交互步骤达到最先进准确率。最后，在 Unitree G1 上的真实世界演示无需预先构建地图，即可结合搜索、视觉检查、空间推理与合成手势，展示了在线编程如何将机器人行为扩展到路线跟随和预定义技能之外。

## Abstract
We present ASENA, an embodied agent system that connects general-purpose coding agents to robot sensing, computation, supervised execution, and persistent experience. Agents can write and execute programs, inspect recorded outcomes, repair failures, and reuse notes and executable skills while keeping their model weights fixed. We further introduce ASENA-VLN, a 4B monocular navigation policy that serves as an optional tool within this programmable system. ASENA-VLN predicts body-frame trajectories for both extended routes and short-horizon behaviors using a shared vision-language decoder trained on route instructions, visual question answering, and a newly curated dataset of geometry-derived atomic navigation tasks. As a standalone policy, ASENA-VLN achieves state-of-the-art success rates of 68.7% on R2R and 70.2% on RxR. When integrated with a coding agent, learned navigation improves ASENA's success rate by 11 percentage points on both agentic benchmarks while reducing execution time. Through persistent workspace evolution and simulator feedback, ten passes over recurring 100-task subsets further improve success from 72% to 98% on R2R and from 65% to 89% on RxR. On embodied question answering, ASENA achieves state-of-the-art accuracy with fewer interaction steps. Finally, real-world demonstrations on a Unitree G1 combine search, visual inspection, spatial reasoning, and synthesized gestures without a pre-built map, illustrating how online programming extends robot behavior beyond route following and predefined skills.

## 1. 核心问题与研究动机

- **背景：导航只是任务的一部分。** 真实机器人任务（如“去看看售货机里有没有我桌上的零食，回来告诉我”）需要决定*去哪里搜、看什么、算什么、怎么回答*，下一步动作取决于当前观测，无法预先写死。
- **现有方法的三处缺口：**
  - 学习式导航策略（NaVid / NaVILA / StreamVLN 等）只提供运动能力，缺少任务级规划与交互能力；
  - Code-as-Policies 类工作虽能用程序组合感知与控制 API，但缺乏**与物理结果对齐的反馈、随程序变化仍有效的安全机制、以及跨任务积累经验的持久载体**；
  - Voyager / Reflexion / ASPIRE / ENPIRE 等自改进智能体多面向桌面操作或纯文本反思，未解决**人形全身运动的安全性与导航策略协同**问题。
- **整体含义：** 论文主张“自进化”不必来自权重更新——把执行轨迹沉淀为可复用程序与笔记，让固定权重的智能体在重复任务上持续变好；同时把学习式导航策略降格为**可调用工具**，而非系统主体。

## 2. 方法论

### 2.1 总体框架：写—运行—检查（write–run–inspect）

- **统一接口：** 智能体通过程序访问 360° 相机、LiDAR、里程计、IMU、关节状态；可做几何计算、可视化、MuJoCo 仿真与动作下发。
- **原子技能封装：** 接近物体、穿过门洞、说话、做手势等被包装为可调用技能；智能体可将其组合成更大的可复用技能。
- **执行记录：** 每次运行存为 **MCAP** 日志，对齐传感器/机器人状态、动作、操作员反馈、代码与可视化图，支持回放与故障定位。
- **反思与保留：** 机器人在**运动被禁用**的状态下复盘记录，修订程序并把解决方案写入工作区。

### 2.2 执行 → 经验的转化（核心公式）

- 工作区定义为第 *k* 版：**W_k = (N_k, S_k)**，其中 *N_k* 为笔记、*S_k* 为可执行技能。
- 一个**固定权重的改进器** *I_φ* 利用执行轨迹 *T_k* 与反馈 *f_k* 更新工作区：

  **W_{k+1} = I_φ(W_k, T_k, f_k)**

- 约束：模型权重、策略权重、控制器权重全程冻结；仿真中私有多 worker 可在轮次间写工作区，**冻结评估期间禁止写入**；真机上每次修订后的程序仍须通过独立安全检查与操作员批准。

### 2.3 ASENA-VLN：4B 单目导航策略

- **骨干：** Qwen3-VL-4B-Instruct，扩展出专用 token 词表（共新增 **1,343** 个 token：**660** 轨迹 token + **683** pixel-goal token），VQA 仍用原文本词表。
- **输入：** 最多 8 帧前视历史（按时间近因加权）+ 结构化 JSON 指令（`goal`、`quality`，可选 `end_pose`：目标物/房间/起点 + 空间关系 + 距离）。
- **输出：** 最多 8 个**累积机体坐标系路点** (x, y, θ)，各轴固定分箱离散化，无需单独连续动作头；pixel-goal token 仅作**辅助监督**（不可直接执行，本文所有评测均用轨迹 token）。
- **数据：**
  - 新构建 **9 类原子导航任务**（度量位移、纯旋转、朝向相对目标、精细对齐、房间目标、穿门、走廊跟随、换层等），在 MP3D / HM3D 中用测地距离、可见性与场景几何生成并校验可行性；
  - 混入短时域 ObjectNav、R2R / RxR / ScaleVLN / SRDF，并用 **GPT-5.5** 将原指令重写为统一 JSON 格式；
  - 加入多视图空间 VQA（SenseNova-SI 等）。
  - 数据池规模：轨迹池 **28.422M**、VQA 池 **9.128M**；训练按 **

训练按 **轨迹数据与 VQA 数据混合采样**，并采用分阶段策略以兼顾“动作能力”与“语义理解”：

- **阶段一（轨迹预训练）：** 以原子导航任务与 ObjectNav / VLN 轨迹为主，学习路点 token 的生成分布；此阶段 pixel-goal token 与轨迹 token 同步训练，使模型在“指向性”与“可执行性”之间建立耦合。
- **阶段二（混合正则）：** 提高空间 VQA 与 JSON 指令解析样本的比例，抑制纯轨迹训练带来的语言与指令理解退化；该阶段对轨迹 token 采用较低学习率，避免破坏已收敛的动作分布。
- **阶段三（格式对齐）：** 用重写后的统一 JSON 指令做轻量微调，使模型稳定接受 `goal` / `quality` / `end_pose` 三段式输入，并对缺省字段（如无 `end_pose`）具备鲁棒性。
- **推理侧：** 单次前向输出至多 8 个累积机体坐标系路点，由底层控制器插值执行；模型保持 4B 量级以适配机上算力，作为**可选工具**被上层编程智能体按需调用，而非每步都必须调用的主干。

### 2.4 安全与可验证性设计

论文把安全拆成三层，且都服务于“程序会随迭代改变”这一前提：

1. **执行前静态检查：** 每次工作区更新后的程序须通过独立的安全检查器（速度/加速度上限、关节限位、禁入区域、动作时长上限），真机上还需操作员显式批准。
2. **执行中运行时监控：** 原子技能内部封装急停、超时与碰撞回退；异常触发后日志被标记，进入下一轮反思。
3. **执行后审计：** MCAP 记录支持逐帧回放，使“哪一行代码导致了哪一次异常运动”可被定位，从而把失败转化为可写入工作区的经验条目。

这层设计的关键在于：**安全约束不依赖于程序的具体内容**，因此当智能体改写技能时，约束仍然有效。

## 3. 实验设计

### 3.1 评测维度

论文将评测分为三类，以区分“单步能力”与“系统能力”：

- **导航策略层：** ASENA-VLN 在原子导航任务与 VLN / ObjectNav 基准上的成功率、SPL、导航误差与朝向误差；重点考察度量位移、纯旋转、穿门、换层等“非语义”能力。
- **智能体层：** 在仿真中设置多轮重复任务族，观察**同一任务在多次尝试后的成功率提升曲线**，以此作为“自进化”的直接证据。
- **真机层：** 在 Unitree G1 上执行需要“搜索—判断—返回汇报”的复合任务，报告完成率、人工干预次数与安全性事件。

### 3.2 对照设置

- 无工作区的固定智能体（每次从零开始）；
- 仅有笔记、无可执行技能的变体；
- 仅有技能、无笔记的变体；
- 不使用 ASENA-VLN、仅用几何/经典规划作为导航工具的变体；
- 以及直接调用通用 VLN 策略（NaVid / NaVILA / StreamVLN 类）作为导航模块的变体。

## 4. 主要发现（论文主张）

1. **自进化可在冻结权重下发生。** 随轮次增加，任务成功率上升且人工干预下降，改进主要来自工作区中新增/修订的技能与笔记，而非模型变化；这为“经验即参数”的观点提供了系统级证据。
2. **笔记与技能互补。** 仅技能时，智能体倾向于重复犯同类错误（缺少“为什么失败”的记录）；仅笔记时，改进停留在文字层面而无法转化为可执行行为。两者同时存在时增益最大。
3. **导航策略作为工具优于作为主体。** 把 ASENA-VLN 封装为可调用技能后，系统在需要任务级推理的场景中明显优于端到端 VLN 策略；而在纯运动精度指标上，专用策略仍具优势——说明二者是**分工而非替代**关系。
4. **安全前置不阻碍进化。** 静态检查 + 操作员批准带来的额外开销可接受，且显著降低了危险动作的发生；论文强调这是真机部署的必要条件而非性能折衷。
5. **小模型足够。** 4B 级策略在机上可实时运行，说明“导航工具”不必依赖超大模型，算力应更多留给上层推理与反思。

## 5. 局限与待澄清之处

- **进化的可迁移性未充分验证：** 工作区是在特定机器人本体与场景分布上积累的，跨本体、跨场景的迁移能力缺少系统评测。
- **评测规模与统计强度：** 真机实验受硬件与安全审批限制，样本量通常有限；仿真中的多轮进化实验虽可重复，但与真实世界的分布差异仍是隐患。
- **反思质量依赖日志与反馈：** 若操作员反馈稀疏或日志对齐存在时延，反思可能退化为无效改写；论文对此仅给出定性讨论。
- **安全机制的完备性：** 静态检查器本身由人编写，其覆盖面决定了系统的安全上界；对“检查器未覆盖的新型动作组合”缺少形式化保证。
- **pixel-goal token 仅作辅助监督**，未在闭环中实际执行，其潜在价值（如细粒度对齐）尚未被充分挖掘。
- **数据构建成本：** 9 类原子任务与 GPT 重写的 JSON 指令管线依赖大量场景几何校验与人工设计，复现门槛较高。

## 6. 评价与启示

- **概念层面的贡献大于单点指标：** 论文最有价值之处是把“自进化”从“训练更好的模型”重构为“维护更好的工作区”，并给出了可操作的工程闭环（统一接口 → 原子技能 → MCAP 记录 → 禁动反思 → 写回工作区 → 安全检查）。这一范式对具身智能体的长期部署具有直接参考意义。
- **方法论上的克制值得注意：** 把学习式导航策略降格为工具、把安全约束与程序内容解耦、把评测拆成策略层/智能体层/真机层，都是避免“用大模型掩盖系统缺陷”的务实选择。
- **仍需补强的地方：** 若要支撑“自进化”这一强主张，需要更长时程、更多任务族、跨本体的实验，以及对“工作区增长带来的检索与冲突管理问题”的讨论——当技能库与笔记规模上升时，如何避免冗余、冲突与错误经验固化，是这一范式走向实用的关键瓶颈。
