## 摘要
具身大脑（即系统2）必须将抽象目标转化为动作，同时发现相关场景条件，并检查已执行的技能是否达到预期效果。开环评估无法测试由智能体决策所塑造的观测，而一些闭环评估在执行过程中提供的证据有限，或假设技能结果理想化。我们提出 SCOPER，一个用于研究基于观测的规划、执行与恢复的套件。SCOPER-bench 结合了高层目标、持续视觉观测、用于低层动作的共享规则式系统1，以及受控的执行失败。其构建与验证流程在 BEHAVIOR 和 ProcTHOR 中生成870个任务，并辅以约3,500个与受评智能体执行过程相关的情境问题。基准测试结果揭示了在保留场景证据、监控进度以及从意外结果中恢复方面的困难。为解决这些困难，SCOPER-harness 将证据记忆与进度验证同动态任务议程和有界探索相结合，且无需额外模型训练。在两个受评开源骨干模型和两个模拟器上，该 harness 将任务成功率提高了11.1–28.6%；一个经 harness 增强的9B模型在两个模拟器上均优于直接执行的27B模型。在一项使用200个真实机器人演示观测的离线下一动作评估中，该 harness 还将完整调用准确率提高了14.7%和15.3%。SCOPER 为在整个完整任务执行周期中诊断和改进具身推理提供了环境。

## Abstract
An embodied brain, or System 2, must turn an abstract goal into actions while discovering relevant scene conditions and checking whether executed skills achieved their intended effects. Open-loop evaluations cannot test observations shaped by an agent's decisions, while some closed-loop evaluations provide limited evidence during execution or assume idealized skill outcomes. We introduce SCOPER, a suite for studying observation-grounded planning, execution, and recovery. SCOPER-bench combines high-level goals, ongoing visual observations, a shared rule-based System 1 for low-level actions, and controlled execution failures. Its construction and validation pipeline yields 870 tasks across BEHAVIOR and ProcTHOR, complemented by about 3,500 situated questions tied to the evaluated agent's execution. Benchmark results reveal difficulties in retaining scene evidence, monitoring progress, and recovering from unexpected outcomes. To address these difficulties, SCOPER-harness combines Evidence Memory and Progress Verification with a dynamic task agenda and bounded exploration, without additional model training. Across two evaluated open-source backbones and two simulators, the harness improves task success by 11.1-28.6%; a harnessed 9B model outperforms a directly executed 27B model on both simulators. In an offline next-action evaluation using observations from 200 real-robot demonstrations, the harness also improves full-call accuracy by 14.7% and 15.3%. SCOPER provides a setting for diagnosing and improving embodied reasoning throughout a complete task execution cycle.

- **核心论点**：动作—结果回路本身不足以构成研究具身 System 2 的条件；必须把“观察塑造决策、决策塑造后续观察”的耦合关系纳入评测，才能诊断证据保持、进度监控与异常恢复能力。
- **整体含义**：论文提出 **SCOPER 套件**（SCOPER-bench + SCOPER-harness），为“完整任务执行周期”的具身推理提供可诊断、可改进的统一实验环境，并给出“无需训练的外挂式 harness 可显著提升现有模型闭环表现”的实证。

## 二、方法论

### 2.1 总体思路
- 将 **System 2（高层规划/推理）与 System 1（底层技能执行）解耦**：所有被评模型共享同一套规则式 Oracle System 1，从而把性能差异归因于高层推理，而非底层控制能力差异。
- 用 **高层目标 + 持续多帧视觉观测 + 可控执行失败注入** 构造闭环任务，并以**情境问答（situated QA）**补充对场景理解与进度理解的细粒度测量。

### 2.2 SCOPER-bench 的任务形式化
- 任务实例表示为 **T = (x, R, C₀, G, E, Q)**：
  - `x`：自然语言指令（只给目标与约束，不给动作序列）；
  - `R`：对象角色约束；`C₀`：初始条件；`G`：目标谓词；`E`：可选执行事件（失败/扰动）；`Q`：挂载问题。
- **四类任务组**：Routine Execution（常规执行）、Observation-dependent（观测依赖）、Failure Recovery（失败恢复）、Composite（2–3 个子任务组合，含跨步依赖）。
- **信息边界**：模型只能看到指令、工具定义、公开词表、动作请求历史与工具返回图像；角色绑定、参考分解、特权状态、事件标签均不暴露。

### 2.3 Oracle System 1 与受控失败
- **统一技能接口**：导航（A* 搜索 + 可通行图）、扫描、目标搜索、抓取、放置/释放、开/关、开关设备、清洗、切割、加热/冷却等；操纵**绕过底层物理接触动力学**，直接更新位姿、持握/包含关系与任务状态，并同步渲染视觉表示。
- **观测机制**：导航/扫描/搜索返回最多 8 帧过程观测；状态改变类动作返回前—后两帧图像。
- **六种执行失败机制**：抓取滑脱、放置掉落、部分打开、部分关闭、错误目标导航、不完整导航；另有**场景扰动**（容器重新闭合/打开、设备状态翻转、物体重新变脏、物体移位等），在指定里程碑后触发。

### 2.4 构建与验证流水线
- 模板 → 场景匹配（类别/可供性/空间约束）→ 角色绑定 → 初始化（含脏盘等“待发现”问题的布置）→ **静态检查**（可达性、可见性、连通性、目标非平凡）→ **特权 Oracle 教师执行验证**（含失败注入任务必须能恢复完成）→ 轨迹生成 → **情境 QA 挂载**。
- 最终在 BEHAVIOR 与 ProcTHOR 上产出 **870 个任务**（BEHAVIOR 420 + ProcTHOR 450）与 **约 3,500 个情境问题**（8 类 QA 模板：目标状态、空间关系、动作结果、活跃问题、新增强制要求、剩余要求、执行中进度、组合进度）。

### 2.5 SCOPER-harness（免训练外挂）
- **Evidence Memory（证据记忆）**：`M_t = (F_t, I_t, O_t)`，分别记录**事实**（对象属性/关系/场景描述，带证据与有效性标注）、**事件**（执行偏差及处理状态）、**义务**（未完成的观察/操作需求）。
  - 观测更新区分 **discovery（发现）** 与 **reconciliation（核对）**：确认刷新证据、矛盾使事实失效、**“看不见”本身不构成否定**；由确定性 commit 层校验引用、证据链与一致性。
- **动态议程（Dynamic Agenda）**：由指令初始化需求项（required / ongoing / conditional；pending / active / watching / supported / blocked），证据提交后触发议程修订（激活条件需求、补充必要工作、合并重复、重开受影响项）。**“发现条件成立”只激活工作，不等于“已完成”**。
- **Progress Verification（进度验证）**：对导航与操纵动作，用请求、预期效果与前后帧判定 **success / failure / ambiguity**；成功提交效果、失败登记事件与恢复义务、歧义保留未确认状态。恢复阶段按 held / released / unknown 分支决定“返回目的地 / 定位重取 / 先补观测”。
- **Anti-deadlock Control（防死锁）**：对扫描/搜索/导航按语义目标计数（默认每目标 2 次扫描、2 次搜索、2 次导航，总观测 4 次、准备调用 6 次），超限则限制工具并请求重选；恢复默认 2 轮重试，放置恢复最多 8 个恢复动作；允许保留**临时规划假设**（不得作为已验证事实、不得支撑议程完成）。
- **动作选择**：`a_t = π_θ(x, V_t, H_t, A_t, f_M_t, c_t)`，其中 `V_t` 为最近 4 帧、`H_t` 为公开请求历史、`f_M_t` 为路由后的记忆、`c_t` 为控制上下文（可用工具、恢复阶段、动作限制）。所有模型组件共享同一固定参数骨干，仅通过角色提示区分。

## 六、主要结论与发现

1. **完整闭环执行本身很难**：最强直接执行模型 GPT-6 Astra 仅达 **50.5%（BEHAVIOR）/ 35.1%（ProcTHOR）**；Qwen3.8-27B 为 14.8% / 21.1%。通用能力（可靠工具调用、多步推进、结果监控）比“具身专用微调”更关键——**四个具身专用模型均未表现出稳定优势**。
2. **失败模式集中在证据与进度控制**：6 个开源模型的 4,813 个失败 episode 中，**47.7% 过早停止、30.7% 耗尽动作预算、40.2% 出现至少三次连续相同工具调用**、12.8% 解析失败、17.3% 引用绑定问题。
3. **harness 带来一致且显著的提升**：整体 SR 提升 **+24.8/+28.6 pp（BEHAVIOR）** 与 **+16.9/+11.1 pp（ProcTHOR）**（Qwen3.5-9B / Qwen3.8-27B）；SR、Prog.、Cov. 在每个任务组、每个骨干、每个后端上均提升。
4. **小模型 + harness 可超越大模型直接执行**：Qwen3.5-9B + harness 在两个模拟器上均超过直接执行的 Qwen3.8-27B。
5. **消融验证组件分工明确**：
   - 去掉 **Anti-deadlock** 整体 SR 下降 **11.8 / 17.6 pp**（ProcTHOR / BEHAVIOR），说明“探索—执行预算平衡”是持续进展的关键；
   - 去掉 **Recovery

- 去掉 **Recovery** 主要损害 **Failure Recovery** 组（该组 SR 显著下滑），而其他组的下降幅度小得多，说明恢复模块的作用具有任务针对性，而不是普遍性的“多给几次重试”带来的红利；
   - 去掉 **Memory** 使 **Observation-dependent** 与 **Composite** 组受损最重（依赖跨步证据保持与义务追踪），同时 Prog./Cov. 也同步下降，说明证据记忆不是单纯提升“回答 QA”的辅助模块，而是支撑目标推进的核心结构；
   - 三者叠加（即直接执行）的退化幅度大于任一单项移除之和的部分，提示组件间存在互补性（防死锁限制无效探索、记忆提供修订依据、恢复把失败转化为新的义务）。
6. **QA 结果与执行结果同向但不同构**：harness 显著提高情境问题的**触发率**（即模型确实走到了需要回答该问题的状态），触发后的准确率在多数分组上升；个别分组出现触发率升、准确率降，作者解释为“更难的问题被激活”，这一解释合理但未被独立验证。
7. **盲测确认视觉必要性**：将全部图像替换为黑图后，所有模型的 SR 与 QA 准确率均大幅下降（含 GPT-6 Astra），说明基准上的表现不能被纯文本先验或指令—动作模板短路解释；同时观测依赖组与组合组的跌幅大于常规执行组，与任务设计意图一致。
8. **真实机器人离线评测**：在 AgiBotWorld2026 的 200 条演示上，直接执行模型在常规节点尚可，但在 **observation-critical** 与 **repair-decision** 节点上准确率明显下滑；harness 对这两类节点的增益最大，说明其价值集中在“需要补看证据”和“需要判断是否修复”的位置，而非一般性的动作生成。

## 七、局限与待解决的问题

- **System 1 的理想化**：Oracle System 1 绕过接触动力学、直接更新状态并同步渲染，虽然换来了可控性与可归因性，但也使“感知噪声、物理不确定性、技能本身的鲁棒性”被排除在研究范围之外；真实系统中高层推理与底层失败的耦合可能更强。
- **失败注入是脚本化的**：六类失败与场景扰动均由规则在里程碑处触发，分布与真实故障的长尾形态不同，模型可能学到“失败总在特定阶段发生”的隐含规律。
- **harness 泛化性证据不足**：仅在 Qwen3.5-9B / Qwen3.8-27B 上验证，未覆盖 API 模型与四个具身专用模型；考虑到 GPT-6 Astra 搭配 harness 因成本高、收益有限而未纳入完整对比，“外挂式结构化记忆是否对强模型同样有效”这一问题仍开放。
- **情境 QA 的可比性问题**：QA 随执行路径动态挂载，导致不同模型/不同方法回答的并非同一题集，触发率与准确率必须联合解读，跨方法比较存在结构性歧义。
- **真实机器人环节是离线的**：固定历史下的下一步工具调用预测无法体现“主动获取观测”“承担自身错误后果”“多步持续恢复”，与论文主张的闭环理念之间仍有落差。
- **成本**：harness 带来约 **3.7 倍**模型调用量，论文未报告 token、延迟或金额的绝对开销，也未讨论在预算受限场景下的降级策略。
- **统计报告**：主表以点估计为主，未见置信区间、多种子方差或显著性检验；在 420/450 episode 的规模下，若干分组间的差异（尤其 QA 准确率）可能落在噪声范围内。

## 八、启示与可延伸方向

- **评测范式层面**：把“观测—决策”耦合、执行中间帧、可控失败与粗粒度指令四者结合，是区分“会调用工具”与“会完成任务”的关键设计；这一思路可迁移到移动操作、桌面整理、多智能体协作等需要长程证据保持的领域。
- **方法层面**：论文的实证支持一个判断——**在固定骨干上外挂结构化的证据/义务/进度表示，比单纯扩大模型或做领域微调更能提升闭环可靠性**。这对资源有限的具身系统落地具有直接价值。
- **可延伸的实验**：① 把 harness 移植到 API 模型与具身专用模型，检验“结构化脚手架”与“模型能力”的交互关系（是替代还是互补）；② 用学习式失败模型替代脚本化注入，考察长尾故障下的恢复；③ 引入真实机器人闭环（而非离线下一步预测），测量“主动观测”的实际收益与代价；④ 对 QA 采用固定题集回放或反事实评估，消除路径依赖带来的可比性问题；⑤ 报告成本—性能曲线，给出预算约束下的 harness 配置建议。

## 九、总体评价

论文的核心贡献不在于提出新的模型，而在于**重新定义了“具身 System 2”的可测边界**：通过解耦 System 1、保留过程观测、注入可恢复失败、并剥离细粒度分步指令，把一个常被“开环 QA 分数”掩盖的能力问题转化为可诊断的闭环实验。其结论——当前最强模型在完整任务周期上仅约 50%/35% 成功率，且失败高度集中于过早停止、预算耗尽与重复调用——为后续工作提供了清晰的问题坐标。SCOPER-harness 作为免训练外挂取得 +11~+29 pp 的一致提升，进一步说明**结构化的证据管理与进度验证是当前具身智能体最经济的改进杠杆**。

同时应客观看待其证据强度：单一 Oracle System 1 的理想化设定、脚本化失败、harness 仅在两个开源骨干上验证、离线真实机器人评测，以及缺少显著性检验，都使部分结论（尤其是组件贡献的精确归因与 QA 层面的收益）仍需更强证据支撑。总体而言，这是一篇**问题定义清晰、实验设计有针对性、结论方向可信但外推需谨慎**的基准与方法论文。
