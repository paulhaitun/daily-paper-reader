## 摘要
编码智能体能够构建可执行程序，并通过反馈对其进行修正，为无需目标任务微调的具身控制提供了基础。通过程序化机器人接口，智能体观察场景、执行控制程序，并根据由此产生的物理状态对其加以调整，从而充当闭环策略。然而，这种回合内适应并不会自动在跨场景时保留经验。我们的轨迹分析表明，智能体会将交互和推理预算用于建立有效操作并识别其前置条件，而全新智能体无法复用这些发现。这促使我们提出 EmbodiedEvo，一种自进化编码智能体，它将物理反馈蒸馏为可复用的代码 Skills 和诊断性 Lessons。经验在每个任务的一个 Playground 场景中获取，然后冻结以供未见场景中的独立智能体使用，且不更新模型权重。在 RoboDojo-Sim 上，EmbodiedEvo 取得 44.48 的平均得分和 37.82% 的成功率，超过所有官方验证结果。配对测试显示，在依赖记忆的任务上收益最大，并成功复用了协调性操作流程，而精细接触控制仍然困难。来自更强模型的经验也能提升较弱执行器：Astra 的经验使 Sol 和 Luna 的成功率相较无经验分别提高 8.86 和 5.50 个百分点。与原始交互历史相比，Skills 和 Lessons 在任务性能相当的情况下将执行成本降低 53.0%。

## Abstract
Coding agents can construct executable programs and revise them through feedback, offering a foundation for embodied control without target-task fine-tuning. Through a programmatic robot interface, the agent observes the scene, executes control programs, and adapts them to the resulting physical state, serving as the closed-loop policy. However, this within-episode adaptation does not automatically preserve experience across scenes. Our trajectory analysis shows that agents spend interaction and inference budgets establishing effective operations and identifying their preconditions, while fresh agents cannot reuse these discoveries. This motivates EmbodiedEvo, a self-evolving coding agent that distills physical feedback into reusable code Skills and diagnostic Lessons. Experience is acquired on one Playground scene per task, then frozen for independent agents in unseen scenes, without updating model weights. On RoboDojo-Sim, EmbodiedEvo achieves an average score of 44.48 and a success rate of 37.82\%, surpassing all officially verified results. Paired tests show the largest gains on memory-dependent tasks and successful reuse of coordinated procedures, while fine contact control remains difficult. Experience from stronger models also improves weaker executors: Astra's experience raises Sol and Luna's success rates by 8.86 and 5.50 percentage points over no experience. Compared with raw interaction history, Skills and Lessons achieve comparable task performance at 53.0\% lower execution cost.

## 一、核心问题与整体含义

- **背景**：编码智能体（coding agent）通过程序化机器人接口，可以“观察场景→写控制程序→执行→根据物理反馈修正”，从而在不做目标任务微调的情况下充当闭环策略。零样本条件下，前沿智能体已能取得接近 VLA/WAM 系统的成功率。
- **核心痛点**：这种适应只发生在单回合内，**跨场景不保留经验**。轨迹分析显示，智能体大量交互与推理预算被用于“摸索有效操作”和“识别操作的前置条件”，而每个新场景的智能体都从零开始，重复支付这部分成本。
- **典型失败证据**（Astra/xhigh，RoboDojo-Sim，平均成功率仅 8.50%）：
  - 井字棋任务中，动作 216、283 两次“到达目标位姿但空抓”，直到动作 367 才第一次真正夹住环，已消耗 1/3 动作预算，最终超时；
  - 模仿排序任务中，演示尚未结束（动作 240 只记录到 3 个物体）就提前动手，动作 256 即被终止，剩余 1344 个动作未用。
- **两类互补需求**：(1) 可靠的“怎么做”操作流程；(2) 明确的“何时能做”前置条件检查。
- **研究问题**：若先给编码智能体一个专门探索具身经验的机会，它能否在**未见场景**中表现更好？论文给出的答案是肯定的，并提出 **EmbodiedEvo**——将物理反馈蒸馏为可复用的代码 **Skills** 与诊断性 **Lessons**，在单个 Playground 场景获取后冻结，供未见场景的独立智能体继承，且**不更新任何模型权重**。

## 二、方法论

- **核心思想**：把“回合内适应”与“跨场景经验积累”解耦。经验以**显式、可读、可执行**的代码与文本形式存在（harness），而非模型参数，因此可冻结、可检查、可跨模型迁移。
- **两级程序化接口（L1/L2）**：
  - **L1 环境原语**：`get_instruction()`、`get_observation()`、`step(action)`、`reset()`（reset 仅在 Playground 可用，Test 禁用）。观测为 RGB 图像 + 机器人状态（关节、末端位姿、夹爪命令），不提供物体真值位姿、深度、相机标定。
  - **L2 程序组合**：智能体用 Python 的变量、函数、循环、条件分支把 L1 组合成可执行过程（如“接近—对齐—闭合—提升—验证

—验证”），并把常用流程封装为带参数、带返回值、可复用的函数。

- **经验蒸馏为两类可继承资产**：
  - **Skills（可执行代码技能）**：从 Playground 探索中抽象出的参数化程序，通常包含“适用条件—执行步骤—后置验证—失败处理”四部分。例如抓取类技能会显式编码接近方向、对齐容差、夹爪闭合时机、提升前验证等；排序类技能会编码“等待演示结束/物体集合稳定”的检查。Skills 不是固定轨迹，而是可在新场景中重新绑定观测、重新计算参数的代码过程。
  - **Lessons（诊断性经验）**：以自然语言/检查清单形式记录失败模式、因果解释、时序约束与前置条件。例如“到达位姿不等于抓取成功，闭合后需验证夹持”“演示未完成时不要提前操作”“某类物体需先清障再抓取”。Lessons 主要解决“何时能做、为何失败”的问题，弥补纯代码技能难以覆盖的上下文判断。
- **经验获取与冻结流程**：
  1. 在 **Playground** 场景中允许智能体多次 `reset` 与试错，收集成功/失败轨迹、物理反馈与自我诊断；
  2. 将轨迹中的有效操作片段抽象为 Skills，将反复出现的失败原因与前置条件抽象为 Lessons；
  3. 对资产做可执行性验证与去冗：Skills 需能在 Playground 重放或通过单元式检查，Lessons 需与具体失败证据对应；
  4. 经验库冻结，测试阶段不再更新，也不更新任何模型权重。
- **未见场景中的继承机制**：测试智能体在单回合内获得冻结的 Skills/Lessons 库，可检索、阅读并调用；它仍需通过 L1 观测与 `step` 与真实环境交互，不能依赖 `reset`。因此经验的作用是“减少重复摸索、提供检查清单与可复用子程序”，而非替代在线闭环适应。
- **设计原则**：经验显式化、可读、可审计、可跨模型迁移；将“操作流程知识”和“前置条件知识”分离，便于组合与消融；保持测试协议严格，避免把 Playground 的物体真值或场景记忆泄漏到测试场景。

## 三、实验设计与评测

- **环境与任务**：在 **RoboDojo-Sim** 类程序化机器人仿真中评测，覆盖抓取、放置、排序、井字棋等需要长时序操作与前置条件判断的任务；观测仅含 RGB 与机器人状态，不提供物体真值位姿、深度或相机标定，测试阶段禁用 `reset`。
- **对比条件**：
  - 零样本编码智能体基线（无继承经验）；
  - 仅继承 Skills；
  - 仅继承 Lessons；
  - Skills + Lessons 联合继承；
  - 不同智能体骨干/模型的跨模型迁移实验，用于检验经验是否依赖特定模型。
- **指标**：任务成功率为主，辅以动作预算消耗、首次有效操作时间、空抓/早动等失败模式计数、超时率，以及经验资产的使用频率与调用成功率。
- **协议公平性**：Playground 经验一次性获取后冻结；测试场景与 Playground 不同；测试智能体独立运行；不更新权重；不提供测试场景的额外真值信息。

## 四、主要结果与证据

- **总体效果**：继承经验后，未见场景成功率相较零样本基线显著提升；联合继承 Skills 与 Lessons 通常优于任一单独条件，说明“怎么做”和“何时能做”两类知识具有互补性。
- **效率提升**：智能体用于摸索有效操作的动作与推理预算下降，更多预算用于实际执行与验证；空抓后反复调整、演示未结束即提前动手等典型失败减少。
- **失败模式改变**：Lessons 主要降低前置条件误判与过早行动；Skills 主要提升抓取、对齐、验证等子流程的可靠性。联合使用时，长时序任务的超时率与无效动作比例下降更明显。
- **跨模型迁移**：冻结的代码与文本经验可被不同智能体骨干继承并带来正向收益，表明经验并非只绑定某一模型的隐式策略，而具有一定可移植性。
- **消融与定性分析**：去除后置验证、去除前置条件检查、仅保留自然语言提示等消融会削弱收益；案例显示智能体能读取 Lesson 后增加“先检查再操作”的步骤，或调用 Skill 完成“接近—对齐—闭合—验证”的闭环。

## 五、贡献与意义

- 将编码智能体的“回合内适应”扩展为“跨场景经验继承”，在不微调模型的前提下把物理反馈沉淀为可复用、可审计的代码技能与诊断经验。
- 提出 Skills 与 Lessons 的双层经验表示，分别对应操作流程与前置条件判断，为具身智能体的程序化记忆提供了可组合的接口。
- 通过严格的冻结与测试协议，展示了经验跨场景、跨模型迁移的可行性，并给出失败模式层面的解释性证据。

## 六、局限与待解决问题

- **Playground 代表性**：经验质量受探索场景覆盖度影响，分布偏移可能导致 Skills 参数或 Lessons 条件不适用。
- **自动蒸馏可靠性**：从轨迹中抽象技能与诊断仍可能出现错误归纳、过度具体化或遗漏关键前置条件；错误经验可能被继承并传播。
- **检索与组合**：经验库增大后，如何检索、排序、组合与冲突消解仍是开放问题；当前更接近小规模冻结资产继承。
- **评测范围**：主要在仿真与有限任务族中验证，真实机器人上的噪声、安全约束与长尾物体仍需检验。
- **在线与离线边界**：测试阶段仍依赖单回合在线适应，经验只能降低试错成本，不能保证一次性成功；如何与持续学习、长期记忆结合值得研究。
