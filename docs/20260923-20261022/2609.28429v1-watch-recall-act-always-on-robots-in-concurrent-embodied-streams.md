## 摘要
常在线机器人面对一个永不复位的无尽流：指令不断到达又失效，场景发生变化，而它自身过去的动作会重塑它必须推理的内容。当前的动作模型恰恰为相反情形而构建：固定指令、任务中途无干预、单步推理。在开放式世界中，机器人必须观察实时流以获取远期线索，回忆自身久远的过去动作，并在双臂并发下据此行动。我们提出 ARMS（Always-on Robot in Multi-modal Streams，多模态流中的常在线机器人），一种刻意简单的流式策略：单个预训练 π0.5 骨干网络，辅以三个轻量模块，将实时感知、具身状态和机器人自身过去动作转化为骨干网络在行动前读取的上下文。这些模块异步更新该上下文，因此观察与回忆从不阻塞行动，且双臂可同时行动。ARMS 不发明新机制，而是将这些学习到的上下文提供器与一种智能体因果自历史相结合，该自历史记录哪只手臂在何时做了什么。为在无需额外标注的情况下监督它们，我们构建 ARMS 数据集，其分阶段构建脚本本身从真实双臂遥操作中为每个模块打标签。在该数据集上训练后，ARMS 在组合任务上达到 45%，而我们四个主要基线中最强者为 28%；消融实验证实记忆模块、具身状态头和异步并发均不可或缺。

## Abstract
An always-on robot faces an endless stream that never resets: instructions arrive and lapse, the scene changes, and its own past actions reshape what it must reason about. Today's action models are built for the opposite: a fixed instruction, no mid-task intervention, single-step reasoning. In an open-ended world a robot must watch a live stream for far-future cues, recall its own far-past actions, and act on them under dual-arm concurrency. We present ARMS (Always-on Robot in Multi-modal Streams), a deliberately simple streaming policy: a single pretrained $π$0.5 backbone augmented by three lightweight modules that turn live perception, embodied states, and the robot's own past actions into context the backbone reads before it acts. The modules update this context asynchronously, so watching and recalling never block acting and the two arms act at once. Rather than inventing new mechanisms, ARMS integrates these learned context providers with an agent-causal self-history that logs which arm did what, and when. To supervise them without extra annotation, we build ARMS Dataset, whose staged construction script itself labels every module from real dual-arm teleoperation. Trained on it, ARMS reaches 45% on the combined task against 28% for the strongest of our four main baselines, and ablations confirm the memory module, the embodied-state head, and asynchronous concurrency are each necessary.

# 《Watch, Recall, Act: Always-On Robots in Concurrent Embodied Streams》论文总结

## 1. 核心问题与整体含义

- **背景**：多模态模型正从离线批处理走向对无尽实时流的在线理解；对具身机器人而言，“流式”不是可选项——相机永不关闭、指令随时间到达与失效、机器人必须在同一时间轴上边看边做。
- **现有动作模型的错配**：当前 VLA / 动作模型普遍假设“固定指令 + 任务中途无干预 + 单步推理”，而真实开放世界要求：
  - **Watch（观察）**：持续监视第一人称流，等待可能在很久之后才触发的“常驻规则”（guard，如“凡是被放到你面前的东西都收起来”）；
  - **Recall（回忆）**：回答自指指令（如“把你收起来的第二个放进盒子”），这只能从机器人自身过去动作的记录中获取，当前帧无法提供；
  - **Act（行动）**：在双臂共享、互相扰动同一场景的真实机器人上执行，还需判断两臂是否即将碰撞。
- **核心论点**：难点不在单项能力，而在**三者的组合**；且这本质上是一个**动作问题**而非视频问答问题——若把双臂换成多选题，实时场景、需维持的前景任务、自我扰动的抓取都会消失。
- **现有工作的空白**：已有系统分别覆盖“常在线”“可中断”“有记忆”中的某一面（SwitchVLA、MemoryVLA、VITA-E、Habilis-β、RoboStream），但**没有一个同时做到“主动（proactive）+ 并发（concurrent）”**，即在保持前景任务不中断的前提下，用空闲手臂执行插入动作并写入可查询的自历史。

## 2. 方法论

### 2.1 核心思想
- **刻意简单的设计哲学**：不发明新网络或新规划器，而是保留**单个预训练 π0.5 骨干**（视觉-语言 Transformer + 动作专家，含原视觉编码器），把一切新需求转化为**骨干在行动前读取的上下文（context）**。
- 三个轻量模块各自把一种信号（实时感知、本体状态、过去动作）转成 token 或短句，追加到 π0.5 的上下文中，由骨干自回归输出双臂动作 token。
- 三模块共享**同一骨干与同一上下文接口**，没有独立的 planner / scheduler / arbiter。

### 2.2 关键技术细节

- **异步并发骨架**：模块异步更新上下文，重的动作前向按需读取；感知与记忆在手臂执行期间持续运行、不阻塞，从而实现任务级并发。感知门控**高频**运行以持续“看”，骨干**低频**推理与动作，仅在触发时被唤醒。

- **模块一：流式视觉触发门（watch 算子）**
  - 复用 π0.5 自身的视觉头编码实时流，不新增感知网络（近零新增参数，token 空间与骨干天然对齐）。
  - 对每条活跃 guard 做二值判定：目标物体是否出现且条件成立（fire / keep watching）。
  - 答案为“否”时全速扫描而不唤醒动作专家，保证常在线低成本；为“是”时视觉 token 进入上下文并调用动作专家。

- **模块二：具身状态头（embodied-state head）**
  - 读取当前观测与本体感知，向上下文追加**一句话**，包含两部分：
    - 每只手臂当前的动作原语（grasping / releasing / reaching / idle）；
    - **碰撞检查**：基于当前与意图运动判断两臂是否处于碰撞路径。
  - 例：“left arm is stowing a cup; right arm reaching the plate is clear”。
  - 由此，碰撞规避与双臂协调被降维成骨干可读的一句话，而非覆盖策略的独立几何规划器；路径畅通则派发并发动作，否则串行化。物理执行层另有 joint velocity limits 与人工急停。

- **模块三：自动作记忆（压缩式，agent-causal self-history）**
  - 维护自身过去动作的记忆 H，但**压缩而非无限增长**：每个完成动作被摘要为紧凑条目（做了什么、哪只手臂、对哪个物体、何时），并做条目合并，使记忆与检索在无限流上有界。
  - 收到回忆指令时检索匹配的过去动作，回写为短句（如“earlier the right arm stowed the carrot second, the banana first”），供骨干解析“第二个”。
  - **关键点**：两个同类物体（如两根香蕉）靠“何时、如何被处理”的**来源信息（provenance）**区分，而非外观；检索时用存储的 object ID 在 last-known-identity 假设下匹配。

- **训练方式**
  - π0.5 骨干（含视觉头）从公开预训练权重初始化，再针对双臂场景微调，继承预训练能力。
  - 三个模块在 ARMS Dataset 上训练：具身状态头用数据集派生的动作原语与碰撞标签；记忆模块用记录的动作历史与指令-目标对。
  - **监督来自数据构建过程而非策略 rollout**，避免对被增强策略的循环依赖。

## 3. 实验设计

### 3.1 数据与平台
- **ARMS Dataset（自建）**：
  - 平台为 Cobot Magic 双臂机器人（低成本 Mobile-ALOHA 式遥操作装置）。
  - 约 **200 条 never-reset 分阶段流**（每条数分钟：有人按提示放置物体，双臂同时作业，第三个需求迫使延迟处理）。
  - 约 **1,200 条短技能演示**，覆盖约 **6 个双臂技能**、约 **15 个物体类别**，并含 **≥2 组同类干扰物对**（如两根香蕉）。
  - 可选加入 LIBERO 仅用于扩大规模。
  - **构建脚本即 oracle**：每个模块的标签由分阶段搭建脚本在布置情境时自动写入，无需额外人工标注。
- **两套协议**：
  - **Online 协议（主）**：端到端评分真实执行动作，覆盖四类任务族——A：guard 与前景任务并发触发；B：按语言回忆过去自动作；C：重新定位被自己移动过的目标；D：双臂均忙时新 guard 触发的仲裁。
  - **Probe 协议（借自 OmniPro，非本文贡献）**：只评识别（是否知道何时该对什么动作而不动），与 Online 对照可暴露**感知–动作分离**。
- **六个指标**：cross-interruption recall、foreground-continuation（FG-Res.）、self-history consistency（Hist.）、dual-arm non-interference（Concur.）、overload-ordering（Overload）、PAUC 式及时性；头条指标为**组合任务动作成功率 EAS**（前景完成 + 所有触发 guard 由空闲臂无碰撞完成 + 回忆返回正确物体 + 过载排序匹配优先级标签，缺一即失败）。

### 3.2 对比方法
四个主基线，**均使用与 ARMS 相同的 π0.5 初始化、相同的微调数据与骨干训练预算**：
- **Fixed-rate VLA**：π0.5 骨干 + 滑动窗口，无流式上下文（“一直在动”）；
- **MemoryVLA**：有记忆，但既不能跨插入维持前景，也不记录哪只手臂行动；
- **SwitchVLA**：可中途切换任务，但无可查询自历史；
- **Recognition → Controller**：用最强 Probe 前端驱动朴素执行器，无记忆、无具身状态模块（“能答但不能做”的对照）。
- 另有 **Oracle / Human**（专家遥操作）作为经验上界。

## 6. 主要结论与发现

- **组合缺口真实存在**：每个基线都只占一个“角落”——MemoryVLA 能回忆（Recall 44）但前景在插入下崩溃（FG-Res. 28）；SwitchVLA 能续接前景（58）但无法检索自身过去动作（Recall 15）；Fixed-rate VLA 与 Recognition→Controller 两项皆低。
- **主结果**：ARMS 达到 **EAS 45%**，最强基线 SwitchVLA 为 **28%**（+17 个百分点）；分项为 Recall 72、FG-Res. 76、Hist. 82、Concur. 78、Overload 71、PAUC 68，**高回忆-高续接区域除 oracle 外只有 ARMS**。距人类/oracle 上界（EAS 85）仍有约 40 个百分点差距。
- **缺口在“执行”而非“感知”**：Probe 识别率保持 >80%，而动作成功率在并发与自我扰动下衰减，构成感知–动作分离。
- **每个模块都必要**：去掉记忆 → EAS 32（Recall 72→31）；去掉 agent-causal 标签 → 38（说明增益来自**来源标注**而非记忆容量）；去掉时序顺序 → 36（类别可辨但序数回忆失效）；去掉具身状态头 → 34（FG-Res. 76→58、Concur. 78→68）；硬中断替代异步 → 30（FG-Res. 76→41、Concur. 78→38，降幅最猛，说明“用空闲臂执行”优于“打断前景”）。
- **真机验证**：清杯同时收水果 65/70 vs 基线 20/28；回忆“第二个”60 vs 13；臂间遮挡下重定位 62 vs 18；≥10 分钟不复位长流保持率 67 vs 30（记忆 H 保持有界）。

## 7. 优点

- **问题刻画清晰且有说服力**：用 watch / recall / act 三要素和表 1 的五轴（Always-on、Proactive、Retrospective、Interruptible、Concurrent）精确划出与先前工作的差异，指出“组合而非单项”才是难点，并论证这是动作问题而非视频 QA。
- **方法极简、可复用性强**：不造新网络、不造 planner，只做“上下文供给”，把碰撞仲裁、任务调度等难题统一降维为骨干可读的 token/句子；复用 π0.5 视觉头使触发门近乎零新增参数，工程友好。
- **数据构建即监督**：分阶段搭建脚本天然充当 oracle，为每个模块自动产出标签，规避了额外标注成本与“策略 rollout 造成循环依赖”的问题，是很巧妙的监督来源设计。
- **agent-causal 自历史**：记录“哪只手臂、何时、对什么”而非世界状态，既解决同类物体区分与序数回忆，也避免双臂并发记录相互冲突，是本文最有辨识度的概念贡献。
- **实验对照严谨**：基线共享初始化/数据/预算，闭环真机评测，留出改述，且同时给出 Online 与 Probe 以定位瓶颈；消融按“服务指标”逐项拆解，归因清楚。
- **作者对自身局限坦白**：明确说明真机 demo 用两个不同物体、同类情形另在数据集上量化。

## 8. 不足与局限

- **真机规模小、平台单一**：仅 Cobot Magic 一个平台，约 200 条分阶段流、每片段 N=60；跨本体（不同自由度、不同相机布置、移动底盘）泛化性未知。
- **完整过载（overload）验证不足**：主要依赖数据集 family D，真机未充分覆盖“多需求同时争抢资源”的复杂仲裁。
- **guard 与优先级是预定义的**：常驻规则由人预先给定，过载策略使用数据集固定的优先级分层，未实现 guard 的自主学习或优先级的学习/推断，限制了开放环境适应性。
- **真机 demo 的回忆可能“靠外观”**：演示用香蕉与胡萝卜两种不同物体，回忆可借外观线索；作者承认同类物体情形只在数据集上量化，削弱了真机结论强度。
- **绝对性能仍低**：EAS 45% 远低于人类 85%，说明方法在真实并发场景下仍远未可用；错误模式与失败案例分析较少。
- **算力与训练细节缺失**：未报告训练 GPU 数量/型号/时长、数据采集成本，复现门槛与成本评估困难。
- **依赖既有组件**：异步骨架沿用 Dispider、记忆压缩沿用 MemoryVLA、Probe 协议沿用 OmniPro、骨干为 π0.5，方法的新颖性主要体现在集成与自历史表示上，单点技术贡献偏弱。
- **潜在评测偏差风险**：数据由作者自建自评，虽划分了留出改述，但场景分布、物体集合、指令模板均来自同一构建流程，存在分布偏窄与“同源评测”风险；PAUC 等指标定义细节在正文中未完全展开。

## 9. 可复现性与开放科学评估（承接上节，从“可复现”维度单独展开）

- **可复现的部分**：骨干（π0.5）为公开预训练权重；Probe 协议明确标注借自 OmniPro；五轴对比表（表 1）给出了与 SwitchVLA、MemoryVLA、VITA-E、Habilis-β、RoboStream 的定位差异，读者可据此判断方法的边界。
- **难以复现的部分**：
  - **ARMS Dataset 未说明是否公开**，而其“分阶段搭建脚本即 oracle”的监督设计恰恰是本文最关键的方法论支点，若数据与脚本不开放，该贡献无法被独立验证；
  - **具身状态头的碰撞标签**由脚本派生，但其几何判定阈值、碰撞定义（路径相交？最小间距？）未给出；
  - **异步骨架的时序参数**（感知门控频率、骨干唤醒条件、上下文读取的原子性/一致性策略）缺失，而这类工程细节恰恰决定“并发”能否稳定成立；
  - **指标定义**（PAUC 的具体积分方式、EAS 的判定严格度、Overload 排序匹配的容差）未在正文完整给出，跨论文比较困难。
- **结论**：作为“系统集成型”论文，其可复现性风险主要不在模型，而在**数据构建管线与异步调度的实现细节**；这两项若开源，复现门槛会显著下降，否则读者只能复现“思路”而非“结果”。

## 10. 对领域的启示

- **“上下文供给”是一种被低估的范式**：本文最有价值的不是某个模块，而是证明了一个强预训练骨干 + 三类结构化短上下文（视觉触发 token、本体状态句、自历史句），就能在不新增 planner 的前提下获得任务级并发。这提示 VLA 社区：许多“需要专门架构”的问题（调度、仲裁、碰撞规避）可能只是**上下文接口设计问题**。
- **“来源信息”应成为具身记忆的一等公民**：传统记忆研究关注“世界状态如何变化”，本文指出对自指指令（“我收的第二个”）而言，真正需要的是 **agent-causal provenance**（谁、何时、对什么、以何顺序）。这一区分对长程家务、多机器人协作、以及需要问责/审计的场景都有迁移价值。
- **“感知–动作分离”是可复用的诊断工具**：同时报告 Probe（识别）与 Online（执行）两套协议，能直接暴露“模型知道该做什么但做不出来”的失败模式。这一对照设计值得被后续工作采纳为标准做法，而非本文的一次性分析。
- **“用空闲臂执行”优于“打断前景”**：消融中硬中断替代异步导致 FG-Res. 76→41、Concur. 78→38，是全表最大跌幅。这是一个具有普适工程意义的结论——**并发能力的瓶颈往往在调度策略而非单步策略**。
- **数据构建即监督**的思路可推广到更多“有脚本可依”的场景（厨房备餐、装配、实验室流程），它把标注成本转移到环境搭建上，且天然避免策略 rollout 的分布漂移与循环依赖。

## 11. 值得追问的开放问题（审稿人视角）

1. **guard 从何而来？** 本文的常驻规则由人预先给定。若 guard 需要从演示中习得、或需要判断“这条规则现在是否仍然有效”，方法是否仍成立？这是走向真正开放世界的关键缺口。
2. **优先级是标签还是推理？** Overload 指标使用数据集固定的优先级分层，模型是在“匹配标签”还是“推断优先级”？若换成未见过的优先级组合，性能如何？
3. **记忆的有界压缩会不会丢关键信息？** 条目合并（entry merging）在长流中必然丢失细粒度时序；当指令要求“第三个”或“倒数第二个”时，压缩策略的上限在哪里？
4. **异步并发的一致性边界**：感知与记忆在动作执行期间持续更新，若上下文在骨干前向过程中被改写，是否会出现“读到半新半旧状态”的竞态？论文未讨论这一致性模型。
5. **双臂之外**：碰撞检查被降维成一句话，这在两臂时可行；若扩展到双臂 + 移动底盘 + 人，句子表示是否仍然足够？还是必须回到几何规划？
6. **失败模式分析缺失**：EAS 45% 意味着过半任务失败，但论文未给出失败类型的分布（触发漏检？回忆错序？碰撞中止？前景漂移？）。这对后续改进的指导价值可能高于总分本身。

## 12. 总体评价

这是一篇**问题定义优于技术创新、系统集成优于单点突破**的论文。它的核心贡献有三：其一，用 watch / recall / act 三要素与五轴对比，把一个模糊的“在线具身智能”需求切成了可测量、可消融的具体能力，并论证了“组合”才是真难点；其二，提出 agent-causal 自历史这一有辨识度的表示，把“自指回忆”从外观匹配问题转化为来源追溯问题；其三，用“上下文供给”的极简哲学，把调度、仲裁、避碰统一降维为骨干可读的 token/句子，工程上高度可复用。

它的主要软肋在于**证据强度与贡献新颖度的不对称**：真机仅单平台、小规模、约 150 trials/方法，完整过载主要在数据集上量化，回忆演示又可借外观线索；算力与训练细节缺失；单点技术多为对 Dispider、MemoryVLA、OmniPro、π0.5 的集成。因此它更像一份**高质量的“问题宣言 + 可行性证明”**，而非一个可直接部署的系统——EAS 45% vs 人类 85% 的差距也印证了这一点。

**适用读者**：做 VLA / 具身流式感知 / 长程记忆的研究者，可从中获得问题框架与诊断工具；做机器人系统集成的工程师，可借鉴其异步骨架与“一句话状态”的接口设计。**若只读一节**，建议读消融部分——它最清楚地说明了“并发靠调度而非靠策略”这一反直觉但重要的结论。
