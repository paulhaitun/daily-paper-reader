## 摘要
多模态智能体（MMAs）通过推理、记忆、工具和反馈维持交互，最显著地表现为计算机使用智能体；而机器人系统（RSs）在物理动力学下将感知与执行耦合。我们将多模态具身智能体（MMEAs）定义为将多模态任务推理与物理动作耦合、并根据由此产生的反馈修正决策的目标导向系统。这引出一个核心问题：当多模态智能体从计算机使用转向机器人使用时，什么发生了变化？我们提出 PAPAV，一个统一的以能力为中心的框架，包含五个反复出现的功能：感知当前状态（Perceive）、预判动作效果（Anticipate）、规划可行路线（Plan）、通过接口或身体行动（Act）、验证结果（Verify）。这些能力按功能而非架构定义，使 PAPAV 能够识别三者共有的内容，并进而比较 MMEAs 与 MMAs 以及 RSs。五项物理约束——从部分可观测性到不可验证的结果——使得可预先确定的选择更少，纠错空间也更小。在 64 个基准中，显式评估集中在 Act（行动）上；只有 5 个评估 Anticipate（预判），3 个评估 Verify（验证），使二者在很大程度上被任务成功所掩盖。这些约束也界定了我们所识别的开放挑战。因此，PAPAV 为设计可靠的物理智能体以及衡量全部五项能力的进展（而非仅衡量任务成功）提供了共同基础。

## Abstract
Multimodal agents (MMAs) sustain interaction through reasoning, memory, tools, and feedback, most visibly as computer-use agents, while robotic systems (RSs) couple sensing and actuation under physical dynamics. We define multimodal embodied agents (MMEAs) as goal-directed systems that couple multimodal task reasoning with physical action and revise decisions from the resulting feedback. This raises a central question: what changes when a multimodal agent moves from computer-use to robot-use? We introduce PAPAV, a unified capability-centric framework of five recurring functions: Perceive the current state, Anticipate action effects, Plan a feasible course, Act through an interface or body, and Verify the outcome. Defined by function rather than architecture, these capabilities let PAPAV identify what all three share and then compare MMEAs with MMAs and with RSs. Five physical constraints, from partial observability to unverifiable outcomes, leave fewer choices fixed in advance and less room to reverse errors. Across 64 benchmarks, explicit evaluation centers on Act; only 5 assess Anticipate and 3 assess Verify, leaving both largely hidden behind task success. These constraints also frame the open challenges we identify. PAPAV therefore provides a common basis for designing reliable physical agents and measuring progress across all five capabilities rather than task success alone.

## 1. 核心问题与研究动机

- **核心问题**：当多模态智能体（Multimodal Agent, MMA）从“计算机使用”（computer-use）迁移到“机器人使用”（robot-use）时，究竟发生了什么变化？
- **背景**：两条研究传统长期平行发展——
  - 多模态智能体（MMA）：通过推理、记忆、工具调用与反馈维持长程交互，典型形态是浏览器/桌面/手机上的 computer-use agent。
  - 机器人系统（RS）：在物理动力学下耦合感知与执行，已有成熟的状态估计、任务-运动规划与闭环控制体系。
- **概念界定**：作者将**多模态具身智能体（MMEA）**定义为“以多模态证据引导物理动作、并用动作反馈修正后续决策”的目标导向系统，处于上述两支传统的交汇处。
- **动机缺口**：现有综述多按各自学科划分（计算机使用类 vs. 具身/VLA 类）。虽有 6/10 篇相关综述同时覆盖两端，但“都覆盖”不等于“建立数字—物理类比”——尚无工作把两种设定放在同一能力结构下比较（见论文 Table 1）。
- **整体含义**：开放物理交互既缺少软件提供的结构化状态与直接反馈，也缺少传统机器人中预先设定的作业约束；因此同样的任务循环变得更不可预测、更不容错，更多决策被迫移入交互过程本身。

## 2. 方法论：PAPAV 能力中心框架

- **核心思想**：以**功能而非架构**划分能力单元，把 MMA、RS、MMEA 放到同一坐标系上比较；以**任务级循环**（task-level loop）而非控制 tick 或单次点击作为共同时间尺度。
- **五个功能角色（PAPAV）**：
  - **Perceive**：由多模态证据与交互历史形成任务信念（belief），维护实体身份、关系、不确定性与时效性。
  - **Anticipate**：在动作提交前，对候选动作的后果做条件预测（像素、视频、潜变量、接触、力、任务进度等）。
  - **Plan**：在任务、环境与具身约束下选择并组织可行行动路线，含子目标分解、依赖排序与恢复分支。
  - **Act**：把语义意图落地为接口/身体可接受的动作规格，并在执行过程中保持闭环修正。
  - **Verify**：把动作后证据转化为可驱动后续决策的判定（继续/成功/重试/重规划/失败）。
- **任务循环公式（式 1，文字化）**：
  - 输入历史 \(h_k\) 与目标 \(g\) → Perceive 得到信念 \(b_k\) → Anticipate 得到预测效果 \(b^\Delta_k\) → Plan 得到意图路线 \(p_k\) → Act 产生环境动作 \(a_k\) 与执行进度 \(\rho_k\) → 经域转移/观测模型 \(T_d, O_d\) 得到观测 \(o_{k+1}\) → Verify 得到判定 \(v_k\)，回馈下一轮。
- **MMEA 判定三条件**（用于区分“能力证据”与“整系统归属”）：
  1. 持久的具身任务循环（状态跨多轮物理执行保持，动作可产生可观测物理变化）；
  2. 任务级能力回流（每项能力有可记录的输出并影响后续任务级决策）；
  3. 具身约束承诺（决策显式考虑物理可行性、执行时序与控制约束）。
  - 证据缺失记为“不确定（indeterminate）”；明确缺失则排除出 MMEA 类。
- **可行动作集（式 2，文字化）**：给定信念与具身 \(e\)，可行动作需同时满足几何可行性、动态可行性、安全约束（三类约束函数 ≤ 0）以及执行时间不超过当前步的时间预算。
- **五项物理约束**（框架的分析主轴）：部分可观测性、有限可模拟性、不可逆性、实时耦合、结果不可验证。
- **协调基底**：记忆与编排不被列为第六项能力，而称为 **agentic harness**，负责跨时间连接五项功能。
- **关键边界澄清**：Anticipate ≠ Plan（前者只产出预测先验，排序归 Plan）；Verify ≠ Perceive（前者针对目标特定后验判据，且必须被任务消费）。

## 3. 研究设计：基准策展与能力标注（非训练型实验）

- **性质说明**：本文是**综述/立场论文**，不提出新模型，也不做模型训练或在线评测；其“实验”实为**对 64 个基准的系统性策展与能力标注分析**。
- **语料构成**：64 个基准 = 10 个 MMEA + 23 个 MMA + 31 个 RS；按主要评测域做互斥归类（仅有多模态输入不足以把 RS 基准归为 MMEA）；语料截止 2026-09-08。
- **纳入标准**：有明确任务/环境、有公开协议与至少一项量化指标、与 PAPAV 相关、且证据足以标注能力。
- **标注协议（三级）**：
  - 显式评估（专门任务/指标/受控对比/可观测信号）；
  - 隐式评估（能力被需要，但只体现在端到端成绩中）；
  - 未评估（任务或协议不要求）。
- **防止高估的能力边界规则**：Perceive 必须单独测感知/定位/信息抽取；Anticipate 必须有被计分的后果/风险/反事实预测；Plan 不含路径/运动规划与状态空间搜索；Act 必须测执行有效性而非仅生成描述或未来视频；Verify 必须由**智能体自身**判定成败，外部评测器的检查不计入。
- **对照对象**：不是对比方法性能，而是与 10 篇相关综述在四个维度上做定位对比（computer-use 覆盖、robot-use 覆盖、基准分析、数字—物理类比），仅本文四项全占。
- **指标层面分析**：把基准分为 outcome-only（24）、outcome-augmented（25）、process-diagnostic（15），并统计 process 诊断在三类系统中的占比（MMEA 4/10、MMA 4/23、RS 7/31）。

## 6. 主要结论与发现

- **覆盖极不均衡**：
  - **Act 显式覆盖最强**：MMEA 10/10（100%）、MMA 16/23（70%）、RS 29/31（94%）。
  - **Perceive**：MMEA 7/10（70%）、MMA 10/23（43%）、RS 10/31（32%）。
  - **Plan**：MMEA 7/10（70%）显式；MMA 与 RS **均无显式评估**（分别 16/23 与 13/31 为隐式，其余未评估）。
  - **Anticipate 仅 5/64（8%）显式**；**Verify 仅 3/64（5%）显式**。
- **核心判断**：预测与结果判定这两项能力**基本被任务成功率掩盖**，导致失败难以归因；端到端成绩最有信息量的前提是底层能力也可观测。
- **五项物理约束的后果**：计算机使用中由结构化接口或系统设计预先确定的选择，在机器人使用中重新变成开放决策，因此可靠性取决于智能体能否维持信念、限定预测适用范围、审慎授权承诺、保持执行可见、并及时核验结果。
- **五个开放挑战（OC1–OC5）**：
  1. 持久物理信念：该记住/修正/遗忘什么（遗忘过激 vs. 陈旧信息累积的张力）；
  2. 决策相关预测：值得预测什么（保真度不等于决策充分性，可用“删减预测细节后策略是否改变”来检验）；
  3. 自适应承诺：何时重规划（动作块长度作为可控变量，需在反应性与重规划成本间权衡）；
  4. 不确定性条件下的控制：行动、继续观测还是求助（取决于可逆性、信息价值与犯错代价）；
  5. 从验证中学习：如何把判定转化为可靠且可迁移、可回退的改进，避免验证错误在循环中累积。
- **评测建议**：报告应包含证据来源、验证器与执行器的依赖关系与相关误差、判定时延与干预窗口；恢复收益等因果量需配对试验、分支回放或显式因果估计。

## 7. 优点

- **统一坐标的构造巧妙**：以“功能 + 信息流”而非模块或动作空间定义能力，使一次点击、一次技能调用与一条机器人轨迹可在同一任务循环下比较，避免了架构对齐的不可行性。
- **边界切分有分析价值**：把 Anticipate 从 Plan、Verify 从 Perceive 中析出，直接解释了为何现有基准“看起来覆盖了”实则未测。
- **双重比较结构清晰**：每项能力都做“共享点 → MMEA vs. MMA → MMEA vs. RS”三段式分析，并配 Figure 4–9 的逐行对照，可读性与可复用性强。
- **“能力证据 ≠ 系统归属”的纪律**：三条件判定 + 三级标注 + 防高估规则，显著降低了综述类工作中常见的过度归因。
- **提出可操作的观测性准则**：如“限定信念（qualified belief）”、执行的双向契约（下行授权记录 / 上行执行遥测）、“适用域包络（applicability envelope）”、验证器的证据依赖画像——这些是可落地为日志规范与评测指标的设计建议，而非空泛呼吁。
- **诚实的自我限定**：多处明确标注“这些是分析准则，不是现有系统已报告的属性”“样本为描述性比较”，学术表述审慎。

## 8. 不足与局限

- **无实证验证**：框架的全部价值主张（如“显式评估 Anticipate/Verify 能改善归因”）未被实验检验；论文未提供任何用户研究、标注一致性分析或案例级复现。
- **语料规模与代表性**：64 个基准为策展样本，作者自认非穷尽；检索依赖 Google Scholar 与特定会议，可能存在语言、社区与发表偏倚；对 2026 年前后快速涌现的工作覆盖必然不完整，且语料冻结后易过时。
- **标注主观性**：三级标签由人工判定，未报告标注人数、培训、仲裁机制或一致性系数；Plan/Verify 的“是否被任务消费”这类判断在实际论文信息不足时容易摇摆（大量系统因此落入“不确定”）。
- **分类摩擦**：MMEA/MMA/RS 的互斥归类与“证据谱系非互斥”的表述之间存在张力；边界系统（如 ModularAgent 被称“边界系统”）的处理显示分类并非总能干净落地。
- **概念增殖风险**：PAPAV + 五项约束 + agentic harness + 多组自造术语（qualified belief、bidirectional execution contract、applicability envelope 等）增加了 adoption 成本，且这些概念与既有 HRI/控制/软件工程概念（如可观测性、接口契约、监控理论）的重叠未被系统辨析。
- **应用限制**：所提准则要求细粒度轨迹日志、执行遥测与验证器依赖披露，对现有基准与真实部署的基础设施要求较高；对安全关键场景，框架未给出风险分级或认证路径。
- **比较维度有限**：与相关综述的对比仅停留在“是否覆盖某维度”的布尔层面，未做更细的方法论差异分析；跨家族覆盖率差异也未做统计检验（样本量本身也不支持）。
